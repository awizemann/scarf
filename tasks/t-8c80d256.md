## What shipped
- **Gate:** the composer button renders only when `VoiceLiveReadiness.availability(capabilities:voiceChatMode:)` is `.ready`. `ChatViewModel.voiceChatModeRaw` is read off-main in `refreshConfigDiagnostics`; `nil` reads as chained, so the button stays hidden. Settings > Voice > "Live Voice" shows only when `hasGPTLiveVoice`. It has the `voice.voice_chat_mode` picker (Chained (default) / GPT-Live) via `setVoiceChatMode`, and a note on the OpenAI key on the host, the ~$0.05/min cost and the 3-minute idle end.
- **VoiceTurnHost:** lives in ChatViewModel.swift, because it drives private ACP turn state. It is Mac-only; there is no shared RichChatViewModel code. Rules, per P5b:
  - The bubble is added before any await.
  - `launchPromptTask` marks the turn in flight before handing it off. It was extracted from `sendViaACP`, so typed and voice turns share one prompt path.
  - Voice prompts skip slash/project expansion.
  - Cancel fires `session/cancel` without awaiting it, then waits up to 10 s, and only for a turn Scarf started (`inFlightPromptSessionId`).
  - `isVoiceTurnBusy` = in-flight || `isAgentWorking`.
  - Reply lookup uses `VoiceTurnReply.latest` over the last 8 (id, prompt) pairs.
  - Analytics `messageSent(inputMode: .voice)`.
- **UI:** `VoiceLiveComposerButton` sits next to Send. `VoiceLivePanel` sits above the composer and shows:
  - status orb with mic level, phase label, elapsed time and approximate cost
  - captions, mute, and End (⌘.)
  - vendor notices
  - ended footer with the idle and stop-phrase messages, plus Start Again
  - failure footer: localized message, setup guidance for every `setupHint` case, verbatim redacted detail, Try Again, and an Open Privacy Settings button when the mic is denied
  
  The panel hosts `VoiceLiveMediaHostView` for the whole session. All copy is in `VoiceLivePresentation` (String(localized:)). Controls have VoiceOver labels and accessibility identifiers `chat.composer.voiceLive` and `chat.voiceLive.*`.
- **Teardown (`endImmediately`):**
  - `stopACP` (every ACP teardown: session switch, delete, terminal launch, watchdog)
  - `startNewSession`, `resumeSession`, `continueLastSession`
  - `ChatTranscriptPane.onDisappear` (leaving Chat, terminal mode, window close)
  - `ContextBoundRoot.onDisappear` (window close, server/profile switch)
  - `NSApplication.willTerminate` (best effort)
  
  `start` stops `MessageSpeechService`. The Mac has no auto-speak.
- Permission prompts are unaffected. The panel is inline, not a sheet; the ChatView permission `.sheet` presents over it.

- Fixed: Bot Chat would have exposed the button (the pane is reused and voice turns bypass the bot send route), so it now opts out. A subscript after a count `#expect` in my tests. The failed-state readout showed a meaningless "0:00 · $0.00". Picker labels were truncated.

  - `SettingsWriteReadParityTests`: `setSetting(VoiceChatMode.configKey, …)` is not a literal
  - P38 sweep: subscripts in VoiceLiveTurnNoteContractTests.swift:25/39/74 and PushToTalkControllerTests.swift:228; a 30 s sleep at HermesSpeechServiceTests.swift:508
  - SpawnDisciplineP43 "leaked >= 90" (probably environmental)
  
  The full run also idled for a long time before finishing.
- Design notes:
  - The mic is disabled until the chat has a live ACP session; there is no autostart.
  - Leaving the Chat section ends the session.
  - If ACP drops mid-session (`handleConnectionDied`), voice continues and delegations speak "could not reach Hermes" until the reconnect succeeds.
