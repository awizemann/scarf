## Description

P42 applied round-4 decision 7 (`hermes_cli` argparse: a user-typed option VALUE beginning with `-` exits 2, because `--` protects positionals only) to the cron and kanban builders, which is what the decision scoped. The same live defect exists at every other site that passes user text as a separate option-value token. Enumerated by grep over `scarf/scarf/` + `scarf/Packages/ScarfCore/Sources/` at commit 4275fbfb:

- `scarf/scarf/Features/Webhooks/ViewModels/WebhooksViewModel.swift:134-148` — `--prompt`, `--events`, `--description`, `--skills`, `--deliver`, `--deliver-chat-id`, `--secret` (all free text)
- `scarf/Packages/ScarfCore/Sources/ScarfCore/Services/BotsService.swift:347,351` — `--clone-from`, `--description`
- `scarf/Packages/ScarfCore/Sources/ScarfCore/ViewModels/SkillsViewModel.swift:419,709-710` — `--source`, `--category`, `--name`
- `scarf/scarf/Features/CredentialPools/ViewModels/CredentialPoolsViewModel.swift:365` and `.../OAuthFlowController.swift:116` — `--label`
- `scarf/scarf/Features/Sessions/ViewModels/SessionsViewModel.swift:832,838` — `--format`, `--session-id`
- `scarf/Packages/ScarfCore/Sources/ScarfCore/Parsing/HermesPeerCLI.swift:73` — `--idempotency-key`
- `scarf/Packages/ScarfCore/Sources/ScarfCore/Services/CuratorService.swift:174` — `--skill`
- `scarf/Packages/ScarfCore/Sources/ScarfCore/Parsing/HermesMCPAdd.swift` — the header/env/command options
- `scarf/Packages/ScarfCore/Sources/ScarfCore/Parsing/HermesCronIncidentsParser.swift:84` — `--state` (choices, low risk)
- `scarf/scarf/Features/MCPServers/ViewModels/MCPLoginController.swift:109` — `--flow` (enum, low risk)

The primitive already exists: `HermesCLIOption.joined(_:_:)` in `ScarfCore/Parsing/HermesCLIOption.swift`, whose doc states the validity boundary — plain `store`/`append` options only, never `nargs='+'`, never a positional. Before converting each flag, open its `add_argument` at the target tag in `~/.hermes/hermes-agent` (`git show v2026.9.7:<path>`) and confirm it has no `nargs` (charter C5); an `nargs`-bearing option keeps the two-token form and needs a `--` guard instead.

Tests: `HermesCLIOption.contains/index/value/values` read an argv back in either spelling, so existing assertions migrate mechanically; the new assertions should pin the literal `--flag=value` token, as `HermesCLIOptionP42Tests` does.
