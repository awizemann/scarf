## Description

Found during P1 (t-72900077, commit 0bdbf90): `hermes config set k ""` writes an empty scalar — it does NOT remove the key. GeneralTab's displayLanguages picker carries a comment claiming its empty row "writes no key" (false by set_config_value reading), and memoryProviders has a bare "" row too. Audit all PickerRow surfaces in SettingsViewModel for the same hazard; route true unset through SettingsViewModel.unsetSetting (gated on HermesCapabilities.hasConfigUnset, v0.19+, added in P1) with the same pre-v0.19 fallback pattern BrowserTab now uses.
