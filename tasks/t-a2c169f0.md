## Disposition

### S2 — security mediums + lows
- **M1 image widget URL** — FIXED. `ImageWidgetView.remoteURL` now requires `https` + non-empty host, matching `WebviewWidgetView.webURL`; a refused URL renders a reason instead of silently loading. Closes the `file://` local-file read and the plaintext channel; the beacon property is inherent to any remote image and is documented in place.
- **M2 mini-app `generated` flag** — FIXED. `defaultChecked()` no longer consults it: sensitive permissions are off for every app. The flag defaults to FALSE when absent, so omitting it pre-ticked the dangerous boxes. It survives as a label only (a false claim can now only make an app look *less* safe than it is treated). Consent caption unified.
- **M3 grant self-certification** — FIXED. New `MiniAppGrantSigner`: per-row HMAC-SHA256 keyed by a 32-byte secret minted into the login Keychain (`com.scarf.miniapp-grants` / `hmac-key-v1`). Unsigned/mis-signed rows are dropped at load (default-deny + re-ask), not refused. Per-row so one forgery can't invalidate honest decisions. **Upgrade note: every pre-existing grant is unsigned and will be re-asked once.**
- **M4 absurd project roots** — FIXED. New `ProjectRootPolicy` in ScarfCore refuses `/`, the user home, top-level system dirs, and any root at-or-above `~/.hermes`. Enforced in `project_register` AND `ProjectsViewModel.addProject`. `PathGuard` keeps its own `/` case as defence in depth.
- **M5 slash-command name** — FIXED. `parse` rejects a frontmatter `name` that `validateName` would refuse (previously enforced only on write); `delete(named:)` validates before building a path.
- **LOW cron argv flag injection** — FIXED. `readCronJobs` refuses a template job whose name/schedule/prompt/deliver/skill starts with `-`. Refusal rather than a `--` separator: charter C5 forbids assuming an argv works, and nothing legitimate starts those fields with a hyphen.
- **LOW zip bomb** — FIXED. `enforceArchiveBounds` pre-flights `unzip -Zt` against 64MB archive / 256MB unpacked / 5000-entry ceilings, and the listing subprocess got the timeout C10 requires.
- **LOW uninstall destroys untracked `.scarf/`** — FIXED (see H8).
- **LOW TOCTOU** — DEFERRED, task **t-9c40eb26**. PathGuard's time-of-use re-derivation was verified and extended (`removeProjectDirIfEmpty` re-lists rather than trusting the plan flag). The residual window needs an `openat`/`O_NOFOLLOW` transport primitive that doesn't exist and has no remote counterpart.
- **LOW exporter forwards agent schema** — DEFERRED, task **t-6f770a34**. Values are already excluded (deliberately, documented); what remains is agent-authored free text needing an export-review surface, which is a design change to the export sheet.
- **S1 follow-up: `KeychainEnvMirror.unmirror` slug** — FIXED. Strips the `.env` block only when no other registered project claims the slug (both cached-manifest and name-derived, rows matched by normalized path). Contested slug is left and logged.

### D2 — lifecycle integrity
- **H6 rename propagation** — FIXED. `propagateRenameToRecord` writes the new name into `project.json` through `ProjectStore.save`, after the registry write, best-effort.
- **H7 doctor divergence** — FIXED. New `recordNameMismatch` (medium, safe repair `renameRecordFromRegistry`) and `recordPathDivergence` (high, report-only, distinguishes move from copy).
- **H8 uninstall ghost + untracked content** — FIXED, both halves. Untracked `.scarf/` entries now count as extras (an unlistable `.scarf/` reports ITSELF as an extra — unknown contents are user content); `removeProjectDirIfEmpty` confirms emptiness by re-listing and retries remote directory removal with `rmdir`; the uninstall deletes Scarf's own `project.json`(+`.bak`), which is what stopped the doctor offering to adopt the just-uninstalled project.
- **Name-keyed removal** — FIXED. `removeProject` keys on uuid, falling back to normalized path.
- **Archive semantics** — FIXED, minimally and deliberately: archive pauses the project's cron jobs (`hermes cron pause`, already-in-tree argv) and drops it from `dashboardPaths`/`projectScarfDirs` so the watchers stop; unarchive resumes. Grants are NOT revoked on archive — archive is reversible and unarchive cannot restore consent. Cron calls are detached (C10: one 30s-timeout spawn per job on the main actor would freeze the window).
- **AGENTS.md block on removal** — FIXED. New `ProjectContextBlock.removeBlock`; an unbounded region (begin marker, no end) is left alone rather than guessed at.
- **Grants revoked on removal** — FIXED. `MiniAppGrantStore.revokeAll(projectId:)`, called from the shared `ProjectLifecycleService.cleanUpAfterRemoval` used by both the sidebar removal and the uninstaller.
- **Normalization uniformity** — FIXED. `ProjectStore.loadOrDerive` now normalizes its registry lookup (a raw `==` missed the row on a different path spelling and derived from a uuid-less entry).
- **Move flow** — MINIMUM DELIVERED (doctor reports it honestly); full flow DEFERRED, task **t-6ee07a0e**.
- **Session-map pruning** — NOT IN BRIEF SCOPE, flagged as task **t-682b7f47**.

## Self-audit findings (found and fixed during the pass)
1. **C10 violation I introduced**: `archiveProject`/`unarchiveProject` originally called `setCronPaused` inline — one `hermes cron pause` spawn per job at 30s timeout each, on the main actor, so a wedged remote with six jobs would freeze the window for three minutes. Detached to `Task.detached(priority: .utility)`.
2. `removeProjectDirIfEmpty` was being called on a `.scarf/` that may not exist, logging a false "couldn't list" warning. Guarded with `fileExists`.
3. Accepted, recorded: the grant signing key is per-machine, so grants written by another Mac into a shared remote `~/.hermes` are re-asked here. That is the correct answer (consent belongs to a person at a machine), not a gap.
4. Accepted, recorded: a Keychain that will not hand over the key makes every mini-app re-ask on every launch. Fail-closed by design; Scarf already hard-depends on Keychain access via `ProjectConfigKeychain`.
