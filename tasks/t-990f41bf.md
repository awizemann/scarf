## Artifacts

**Shipped**

- **HIGH — unquoted MCP `env:`/`headers:` map keys: FIXED.** New shared `ScarfCore/Parsing/YAMLScalar.swift` (`quoteIfNeeded`, `containsLineBreak`, `doubleQuoted`, `strippingBOM`, `resolvesToNonString`); `GatewayConfigWriter.yamlQuoteIfNeeded` now delegates to it and `HermesFileService.subMapRows` (new, shared with the callers) quotes keys through the same helper. One quoting routine, not two.
- **HIGH — verifier failed OPEN: FIXED.** `setMCPServerEnv`/`setMCPServerHeaders` pass the exact emitted rows as `patchMCPServerField(expecting:)`, so a key that commented its own mapping out now restores instead of passing. `unpatchableReason` gained `badKeyReason`: rejects a key opened by `{`/`[` or containing a tab. Deliberately NOT `,`/`}`/`]` mid-token — verified with PyYAML 6 that `a,b`, `a}b`, `a]b`, `a{b`, `a[b` all load as plain keys, so rejecting them would make an ordinary config uneditable (test pins the non-refusal).
- **HIGH — duplicate env/header rows trapping the process: FIXED.** `MCPServerEditorViewModel.duplicateKey(in:)` + two guards in `save()` that surface the collision through the existing `saveError` before any write; the dictionary builds switched to `uniquingKeysWith:` so no caller can trap.
- **MED — interleaved comments deleted: FIXED.** `preservedComments` / `trailingComment` in `GatewayConfigWriter`, wired into both `replaceBlock` and `setMapLF`'s `.found` branch. Interior comments are re-emitted directly under the key (a bullet's identity is its value, and the values are what the edit replaces), so the first save reflows once and is then idempotent — pinned.
- **MED — `'` un-doubling: FIXED** in both `HermesYAML.stripYAMLQuotes` and `normalizedScalar` (the latter also switched to the doubling-aware `closingQuoteIndex`; `firstIndex(of:)` stopped at the first half of `''`). Save→read→save idempotence test added.
- **MED — `yamlScalar` line-break guard: FIXED.** Escapes the break double-quoted rather than refusing, and `unquote` now decodes `\n`/`\r` so it round-trips losslessly.
- **LOW — implicitly-typed scalars: FIXED.** `YAMLScalar.resolvesToNonString` mirrors PyYAML's implicit-resolver table (null/bool/int/float/timestamp/merge/value). Both writers quote them. `ssl_verify`'s bool-or-path exception is untouched.
- **LOW — `crlfRoundTrip` mixed endings: FIXED, better than planned.** Not a refusal: `HermesBotProfileYAML` already solved this per line, so that routine was lifted to `ScarfCore/Parsing/YAMLLineEndings.swift` and both writers share it. Surviving lines keep their own terminator; new rows take the dominant one; pure-LF is byte-identical.
- **LOW — `HermesYAML` duplicate list key: FIXED** (last-wins, matching PyYAML).
- **Collateral, required by the implicit-typing widening:** `PowerSettingsWriter` canonicalises a `reasoning_overrides` value of `off` to `none`. `off` only ever meant "disabled" via YAML's bool coercion (bare `off` → `False` → `str(False)` == `"false"`, `hermes_constants.py:876-889` at v2026.9.7); quoted it would load as `"off"`, which is in neither of that function's sets. `false`/`disabled` are accepted as strings and are written as typed.

**NO-OP, with evidence**

- **MED — BOM.** The audit's *consequence* (first section hidden → duplicate appended → siblings clobbered) is NOT reachable through Scarf. Every text read in the app decodes with `String(data:encoding: .utf8)` (`ServerContext.readTextThrowing:426`, `GuardedTextFile:291`, `HermesFileService.readFileResult:2845`) and Foundation's UTF-8 decoder STRIPS a leading U+FEFF — proven with a standalone Swift probe — so no matcher, parser or writer ever sees one, and the BOM's 3 bytes were already lost on the first write with or without P19. The pure-function hardening shipped anyway (writers, `parseNestedYAML`, `trimYAMLLine`, `computeConfiguredPlatforms`) so the invariant is explicit rather than accidental, and `foundationStripsTheBOMBeforeAnyWriterSeesIt` pins the reachability claim so a future hand-rolled `Data` decode surfaces here rather than as a mystery duplicate section. "Preserve the BOM byte-for-byte" therefore holds at the writer boundary only; carrying it further would mean changing the read layer, which is out of phase.

**Fresh-eyes findings on my own diff (all resolved before commit)**

1. `badKeyReason` first rejected any `{}[],` anywhere in a key, which would have refused to edit a config with a legal bare `A,B` env key — and the gate runs BEFORE mutation, so the entry would be permanently uneditable. Narrowed to a leading `{`/`[` plus tab, verified against PyYAML, with a non-refusal test.
2. The mixed-line-ending fix started as a `.refused`. Found `HermesBotProfileYAML.restoreLineEndings` already doing it per line with its own tests — lifted to `YAMLLineEndings` and reused instead, which keeps the edit working.
3. `YAMLScalar.doubleQuoted` initially escaped `\t`, which `HermesFileService.unquote` would have read back as a literal `\t`. Dropped (a literal tab inside a double-quoted scalar is legal and lossless).
4. The float resolver initially over-matched: PyYAML requires a `.` in the mantissa, so `1e3` and `1e+3` are STRINGS and quoting them would be churn. Mirrored exactly, with both in the "stays bare" test.
5. Interior comments necessarily move to the top of the block; documented in the doc comment and pinned with an idempotence assertion rather than left as a surprise.
