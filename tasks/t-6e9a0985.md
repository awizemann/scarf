## Description

Raised by P41 (round-4 decision 10). The round-4 report and decision 10 both list `gateway.multiplex_profile_allowlist` as one of "the three Scarf-written blocks" that should move onto `YAMLScalar.unquote`. It is NOT Scarf-written: a repo-wide grep at `151cdd3e` finds only READS —
- `scarf/Packages/ScarfCore/Sources/ScarfCore/Parsing/HermesConfig+YAML.swift:1014-1056` (`multiplexProfileAllowlist`, both the top-level and the `gateway.` spelling)
- `scarf/scarf/Features/Settings/ViewModels/SettingsViewModel.swift:1107-1122` (`multiplexProfileAllowlistWarning`)
— and the only WRITE near it is the sibling bool `multiplex_profiles` via `hermes config set` (`SettingsViewModel.swift:1213-1223`). `GatewayConfigWriter.saveList` is reached only from `GatewayBehaviorViewModel.swift:176` with `GatewayAllowlistKind.yamlKey`, i.e. `allowed_channels` / `allowed_chats` / `allowed_rooms`.

So P41 opted in only the two blocks Scarf actually writes (`agent.reasoning_overrides`, `model_catalog.excluded_providers`) and deliberately left the multiplex allowlist on `HermesYAML.stripYAMLQuotes`, because widening the escape table for a Hermes-written value is the exact thing `YAMLScalar.unquote`'s doc refuses. Both the opt-in's doc (`HermesYAML.scarfWrittenMapPaths`) and `HermesP41YAMLDecoderTests.theOptInIsExactlyTheTwoBlocksScarfWrites` record it.

Two things to decide:
1. Does the product want an EDITOR for `gateway.multiplex_profile_allowlist`? Today the only surface is `SettingsViewModel.multiplexProfileAllowlistWarning`, a read-only warning under Profile Routes that tells the user a route's profile is not in a list they cannot edit from Scarf — arguably a dead end in the same shape P40b fixed for the `config migrate` hint.
2. If such a writer lands, add BOTH spellings (`multiplex_profile_allowlist` and `gateway.multiplex_profile_allowlist`) to `HermesYAML.scarfWrittenListPaths` in the same commit, and update `theOptInIsExactlyTheTwoBlocksScarfWrites`.

Also worth doing while here: the same MED class applies to every platform allowlist written by `GatewayConfigWriter.saveList` through `YAMLScalar.quoteIfNeeded` (`slack.allowed_channels` etc.) and read back through `stripYAMLQuotes`. The round-4 finding did not list those; P41 did not widen scope to them. Decide whether they join the opt-in.
