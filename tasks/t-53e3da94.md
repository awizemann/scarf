All seven findings were real and all seven are fixed. No disputes.

**1. Skills diff on edit.** `CronViewModel.skillEditArguments(existing:newSkills:clearSkills:)`
(new, `nonisolated static`, called from `updateJob`; `existingSkills` is now a REQUIRED
parameter so a future caller cannot silently get append-instead-of-replace).
Empty target set → `--clear-skills` (omitted entirely when the job already had none);
non-empty → `--remove-skill`/`--add-skill` diff, never a `--skill` replacement.
`CronView` passes `job.skills ?? []`.
*Floor walk (the assigned work):* `--clear-skills` / `--add-skill` / `--remove-skill`
walked over EVERY tag and BOTH locations. First tagged `v2026.3.17` = **v0.3.0**
(`hermes_cli/main.py:2854-2857`, all three on `cron_edit`), absent at `v2026.3.12` (v0.2.0);
moved to `hermes_cli/subcommands/cron.py:98-104` at `v2026.6.19` (v0.17) and unchanged at
`v2026.9.7`. **v0.3.0 is below Scarf's minimum supported Hermes (v0.6.0), so the correct
outcome is no gate.** There is therefore no "below the floor" argv to keep — the honest
"each side" test is `skillArgvIsIdenticalOnTheOldestSupportedHost`, which pins that a
v0.6.0 host (`isV0206OrLater == false`) and a v0.21.1 host get byte-identical flags and
that the builder takes no capabilities.

**3. Doctor ids with spaces.** `HermesCronDoctorParser.parse(text:knownJobIDs:)` +

snapshots `Set(jobs.map(\.id))` on the main actor; `load()` re-runs the doctor when the
roster changes AND the doctor has already answered (the cold-launch order otherwise leaves

**4. `_ensure_aware`.** Comment on `parseHermesTimestamp` corrected (system-local → configured
tz, never UTC, and why UTC is a deliberate stand-in). `oneShotIsUnresumable` split into an

`hermes_cli/cron.py:88-91`. Fresh-eyes addition: `Int(_: Double)` traps on NaN/±inf and
`lateness_seconds` is untrusted JSON, so a non-finite value degrades to `"?"` (Hermes's own
`except (TypeError, ValueError)` arm).

**6. `runAndReload`.** New `refreshDiagnosticsAfterMutation()`, called on BOTH the success

`hasLoadedIncidentList` / `hasLoadedDoctorFindings` — the probe having ANSWERED — so a
pre-v0.20.6 / pre-v0.21 host gains no spawn (C1).
