## Description

S1 root cause (CONFIRMED). Hermes 0.17 returns {} (empty dict, NOT null) for a not-restorable session/load; ACPClient.loadSession's #99 guard (ACPClient.swift:322-327) only throws on nil, so Scarf fabricates success, attaches to a nonexistent session, and the next prompt gets stopReason=refusal ("session may have been cleared" banner). Fix: real 0.17 load successes carry models/modes keys — treat their absence (or empty result) as not-restorable and fall through to the existing newSession fallback. Evidence + probe script: memory note chat-session-layer-mechanism-map-and-2026-07-13-diagnosis; scratchpad acp_load_probe.py.
