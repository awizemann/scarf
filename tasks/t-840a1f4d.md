## Artifacts

Commit `6ce74848` on `fix/whole-surface-audit-r2`. All 8 findings FIXED; no NO-OPs.

**Shipped**
- **Platform setup (HIGH)** — new `PlatformSetupForm` protocol + extension in `PlatformSetupHelpers.swift` owns the off-main load/save choreography; all 15 forms (Telegram, Discord, Slack, Matrix, Mattermost, Ntfy, Signal, SimpleX, Email, Feishu, iMessage/BlueBubbles, Webhook, WhatsApp, WhatsApp Cloud, HomeAssistant) adopt it and take an optional `HermesCLIRunner`. `saveForm` routes `config set` through the runner with a named 15 s cap. Verified at v2026.9.7 that `hermes config set` has no batch form (`hermes_cli/config.py::_cmd_config_set`), so the loop stays sequential. New guards: no save from the pre-load blank form (would `unset` live `.env` keys), no load on top of a save; Save/Reload disabled on `isBusy`; `GatewayBehaviorViewModel` gains the same `!isLoading` save guard.
- **Health (MED)** — `lsof` gets a 3 s timeout via the new reusable `Process.waitUntilExit(timeout:)` (`Core/Models/ProcessTimeout.swift`, reaps the child on overrun) and runs off-main with the whole stop path; `launchDashboard`'s `Process.run()` moved off the main actor. The dashboard server process deliberately keeps no timeout (nothing waits on it) — documented in place.
- **Kanban (MED)** — `lastDiagnosticsFetchAt` now stamps the ATTEMPT; the throttled fetch is factored into `refreshDiagnosticsIfDue(_:)` so it is testable without a live host.
- **Gateway (MED/LOW)** — `HermesGatewayListService.fetch` takes an optional runner (nil in production: it must judge stdout alone) and a named `fetchTimeout`; the five mutations go through `cliRunner` with a named `mutationTimeout` (60 s, unchanged value); `isLoading` is cleared by a separate `inFlightLoadGeneration` so a mutation-superseded load releases the spinner; `GatewayView.attachCapabilitiesIfNeeded` calls the new `cancelLoad()` on the outgoing VM.
- **MCP login (LOW)** — `proc.run()` off the main actor, with a stale-generation branch that reaps a process `stop()` could not see. P21's EOF-then-judge sequencing untouched (handlers installed before the spawn).
- **Skills (LOW)** — `SkillsViewModel` is `@MainActor` as a whole (half-annotating it is what created the hole, and does not compile against the Swift-6 test target); `computeMissingConfig` is now a pure `nonisolated static` and its config.yaml read happens in a `Task.detached`.

**Tests** — new `scarfTests/MainActorSpawnDisciplineP22Tests.swift`, 14 tests, all passing. Revert-verified: reverting `PlatformSetupHelpers.save`'s detachment fails 2 tests / 6 expectations. Suite runs: P22 14/14; P22+P11+P21+CLI-exit-code+Gateway+Health+Kanban+MCP-OAuth 97/97; ScarfCore 2551 tests (4 ACP failures under full parallel load, all pass in isolation — pre-existing flake, unrelated).
