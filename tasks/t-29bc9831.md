## Description

Go/no-go spike on a throwaway branch (feat/voice-spike); code may be reused by P4 but is not merged as-is.

Prove, on macOS AND iOS (simulator acceptable for iOS where mic allows; say what couldn't be tested):
1. Session exchange without the Hermes dashboard: run a host script over ServerTransport.streamScript that calls Hermes's `tools.voice_live.create_webrtc_session(sdp, history)` (and `resolve_gpt_live_status()`), key stays on host. Verify at tag v2026.9.14 (Hermes v0.21.3) source; works for local and SSH hosts.
2. A WKWebView (hidden or minimal) runs RTCPeerConnection + getUserMedia; mic permission works in the sandboxed macOS app (entitlement com.apple.security.device.audio-input exists) and in ScarfGo; echo cancellation OK.
3. Data channel: capture the real event shapes (session.delegation.created, commentary/response events) from Hermes desktop source apps/desktop/src/lib/voice-live.ts + hooks/use-voice-live-conversation.ts at the tag; bridge them to Swift via WKScriptMessageHandler.
4. Handing a spoken request to Hermes over ACP: ACP has no `voice-live` surface (only tui_gateway does, which injects VOICE_LIVE_TURN_NOTE into model input only). Decide how Scarf sends the delegation turn (e.g. prefix the note) and what that means for the saved transcript; recommend the least-bad option.
5. Cost note: gpt-live bills $0.05/min on the host's OpenAI key — keep live tests short.

Output: documents/plans/2026-09-18-live-voice-spike.md with findings (file:line cites), go/no-go, and a concrete design for P4/P5. Memories for durable findings.
