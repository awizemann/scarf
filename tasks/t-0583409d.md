## Description

Reported on Reddit 2026-10-29: starting a few chats in a row, each chat stops when you click into another. Hermes Desktop lets them run side by side.

Diagnosis (Mac, verified in code):
- One chat per window, one `hermes acp` process per chat. Switching (`resumeSession` / `startNewSession` → `startACPSession`) calls `stopACP()` first (ChatViewModel.swift:3048), which sends `session/cancel` for the in-flight turn, stops the process and shows "Turn cancelled — switched sessions." This is deliberate (S4 fix, t-5451bd1b), not a regression.
- The server window is `WindowGroup(for: ServerID.self)` (scarfApp.swift:224), so a second window on the same server isn't a workaround.

Hermes already supports parallel chats:
- One `hermes acp` serves several sessions at once: per-session `runtime_lock`, a 4-worker executor, ContextVars isolated per session (acp_adapter/server.py:47, :734-760 @ v0.22.5; same at v2026.9.24).
- On v0.22.3+ (gateway-backed) a turn keeps running after its viewer detaches; the owner ends a session only when the last viewer leaves with nothing queued (acp_adapter/entry.py:220-221).

Direction: keep the ACP client alive across switches and keep a running chat attached in the background instead of cancelling it; per-session transcript state; a "working"/"finished" marker in the chat list; surface permission and clarify prompts from background chats. Needs a design pass before code (ChatViewModel is single-session throughout). Check iOS (ChatController) for the same behaviour.
