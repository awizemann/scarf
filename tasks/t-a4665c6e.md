## API for P5a / P5b (all in scarf/Packages/ScarfCore/Sources/ScarfCore/)
- Gate: `VoiceLiveReadiness.availability(capabilities:config:)` returns `.ready` or `.hidden(.hermesTooOld | .chainedMode)`. The composer shows the entry only when `.ready`.
- Settings: `VoiceChatMode`. Mac uses `SettingsViewModel.setVoiceChatMode(_:capabilities:)`; iOS uses `IOSSettingsViewModel.saveVoiceChatMode(_:capabilities:)`. Show the OpenAI-key requirement and the $0.05/min cost next to the control.
- UI binds to `VoiceConversationEngine` (VoiceLive/VoiceConversationEngine.swift):
  - properties: `phase` (…, `.failed(VoiceSessionFailure)`; `setupHint` flags the no-key case), `captions`, `micLevel`, `isMuted`, `elapsedSeconds`, `approximateCostUSD`, `notice`
  - methods: `start()`, `end(reason:)`, `endImmediately(reason:)`, `toggleMute()`
  - Localize app-side; `englishDescription` is an English token only.
- Construction: `GPTLiveEngine(bridge: WebViewVoiceMediaBridge(), exchange: VoiceLiveHostExchange(context:), turnHost:)`. Keep ONE engine per chat: its pending-cancel state spans voice sessions.
- Hosting: keep `VoiceLiveMediaHostView(bridge:)` mounted for the whole session.
- Chat side conforms to `VoiceTurnHost`:
  - `submitVoiceTurn`: append the bubble before any await, then `sendPrompt(sessionId:text: request.prompt, images: [], contextNotes: request.contextNotes)`. Pass the notes exactly as given; they are empty for a superseding turn. Return once the prompt is handed to ACP.
  - `cancelActiveVoiceTurn`: cancel, then await sendPrompt's return.
  - `voiceTurnReply(for:)`: use `VoiceTurnReply.latest(in:forPrompt:isStreaming:)`, which also matches Hermes's rewritten "…User correction/guidance after interrupt: <prompt>" row.
- Teardown: call `endImmediately` on window close, session or server switch, quit, and iOS not-active. On iOS, inside `beginBackgroundTask`.

- Fixed in the first audit: the mic/peer leak on end-during-load, ValueError→no_key over-mapping, live on channel open, mute while connecting, a hung page load, cwd shadowing, and a pipe stall in the test runner.
- Fixed in the follow-up audit:

  - A failed iOS stdin write hid the remote's exit status and stderr.
  - Doc corrections.
  - Test hang guards were raised after a 30 s bound tripped at load average ~90.
- Remaining, documented:
  - A user-Stopped typed turn followed by a first voice turn with the note leaves the cancelled prompt for the next typed message. There is no Hermes verb to clear it; it is in the upstream request.
  - If a typed prompt was queued behind the cancelled turn, Hermes drains it first (server.py:927-938) and it consumes the stored text, so that voice turn just loses its note.
  - A text-only voice prompt starting with "/" would be treated as a slash command (unlikely from speech).
  - Mac `SSHScriptRunner.runLocally` still passes local scripts as `/bin/sh -c <script>` argv, on the user's own Mac. A follow-up chip was filed.
