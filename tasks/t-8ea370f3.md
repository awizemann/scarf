## Fresh-eyes audit of the diff

- **Pre-target degradation (C1)** — the real risk of an output-judged verdict. Walked every marker over every tag v2026.6.19→v2026.9.7 at BOTH the old (`main.py`) and new (`subcommands/`) file locations: all byte-identical. `Ran now:` is the only younger one (v2026.7.1) and simply never fires on v0.17. `security audit`'s `--fail-on critical` default and 0/1/2 contract confirmed present at v2026.5.29 — the release the verb shipped in, i.e. the `hasHermesAudit` floor gating the button.
- **`payloadIsValid` decoded the entire stdout** to a String to validate it, doubling a possibly-hundreds-of-MB payload in memory, and a fixed 64 KB byte prefix could cut a UTF-8 codepoint. Rewritten to slice the first line on a newline BYTE inside a bounded window.
- **A leading blank line would have skipped the check** in the first rewrite. Fixed to skip leading whitespace before picking the line, and pinned with `sessionsExportRefusalAfterBlankLinesIsStillRejected`.
- **`friendlyPluginFailure` was `@MainActor`-isolated** and unreachable from the nonisolated test — the app-target compile caught it; made `nonisolated`.
- **Over-broad markers**: `Error:` (skills) and `not found.` (sessions) could occur inside a report body. Safe because `failureWins` is false at those sites, so a genuine success line wins — pinned by `aSuccessMarkerBeatsIncidentalFailureTextByDefault`.
- **C10** — no new main-actor spawn/read; every judgement runs in the existing detached task before the `MainActor.run` hop.
- **C7** — staged by explicit path; no managed tier committed.
