### Items 1-8
1. kokoro removed: service rung, all `tts.kokoro.*` fields/parse/setters/Settings rows, doc mentions.
2. `MessageSpeechService.shared.serverContext` and the scarfApp onAppear are removed. SpeakMessageButton passes `\.serverContext` (window profile scope, or the bot context) and window capabilities in a PlaybackID(server, messageId) on every toggle.
3. Path safety:
   - The script writes into a private 0700 `$TMPDIR/scarf-tts-<uid>/`, refused if it is a symlink or foreign-owned.
   - It announces SCARF_TTS_BASE before Hermes runs; the first line wins.
   - Only Hermes-derived names in that directory are read or deleted. Anything else throws `unexpectedOutputPath` and nothing is touched.
4. Quoting uses the shared `HermesProfileScope.shellQuotePath`: a leading `~` is the only live `$HOME`. Covered by a real /bin/sh test and by a real script run with a hostile HERMES_HOME.
5. Interpreter: `paths.hermesBinary` + `HermesConfigReader.pathPrelude`, then the binary's shebang python, then the python beside `readlink -f`. No bare python3 fallback and no personal paths.
6. `hasHermesSpeechSynthesis` gates both the Playback Engine picker (hidden below 0.20.1, so Settings renders as main does) and engine routing (`PlaybackEngine.resolve`).
7. Cache moved to ~/Library/Caches/scarf/tts with the 256 MB cap kept. The key includes server id + profile home, length-prefixed per field.
8. Config read (detached) and synthesis (actor) run off-main, and temp WAV writes are now detached. Stop cancels the task, and SSHScriptRunner kills the round trip.

### Fresh-eyes audit: findings and resolutions
- A. WAV-only playback meant Hermes's DEFAULT provider (edge, which writes MP3) always fell back to the system voice. Fixed: WAV/MP3/FLAC/AIFF are accepted by magic bytes, chunks must agree, Ogg is a mismatch.
- B. The per-synthesis `find` sweep over a flat $TMPDIR took ~1.5 s on a 166k-entry TMPDIR, and a shared /tmp allowed pre-planted symlinks. Fixed with the private 0700 per-user directory plus the ownership/symlink check.
- C. Stale-callback races:
  - A flushed WAV segment could decrement the next playback's counter. Fixed with a generation token.
  - A system-voice didCancel from a stopped message cleared the new message's state. Fixed with an utterance identity check.
  - A cancelled task's error path could start the fallback voice. Fixed with a `!Task.isCancelled && playing == id` guard.
- D. Message id collision across windows. Fixed: playback is keyed by (server, id).
- E. Duplicate shell quoter. Fixed: replaced with the shared `HermesProfileScope.shellQuotePath`.
- F. `nous` cache fingerprint ignored the openai voice. Fixed.
- G. A read failure skipped server cleanup. Fixed: validated files are removed on every path.
- H. Known limitations, left open:
  - Command/plugin providers fingerprint on the provider name only, so editing `tts.providers.<name>` can serve older cached audio for already-spoken text.
  - The global `tts.speed` is not in the fingerprint.
  - Cancelling mid-synthesis leaves the remote tool running until it finishes; its output is swept after 30 min.
