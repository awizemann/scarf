## Description

During `./scripts/release.sh 3.2.0` (second attempt, serial gate, commit 739b50ef on Alan's Mac, 2026-09-14 10:13), the Full plan reported `SessionDeletedSignalTests.sessionsTabDeleteOnOtherServerContextLeavesChatUntouched()`: "The test runner exited with code 0 before finishing running tests." xcresult: 1462 total, 1459 passed, 1 failed, 2 skipped; all 16 UI tests passed. Log: the host pid 50485 stopped logging ~0.9 s after the test started and a fresh host pid 54433 booted (XCTest relaunch), then the rest of the run passed.

Evidence it is not a product defect: the suite passes 3/3 in serial isolation, the whole Full plan passed serially through `scripts/ui-gate.sh --skip-live` an hour earlier (1442/213), and there is NO process-exit path reachable: `grep exit\(|terminate\(` over `scarf/scarf` and `ScarfCore/Sources` finds only the Quit menu item (`scarfApp.swift:934`), `ProfilesViewModel:118` (after `AppRelauncher.relaunch()`, which throws `.debugBuild` for any bundle under `/DerivedData/` — the gate's case), and the separate `scarf-projects-mcp` binary.

Open questions: what sends a clean exit to the test host (an Apple Event from a stale process of a prior gate run? Sparkle? AppKit last-window-closed — no `applicationShouldTerminateAfterLastWindowClosed` exists)? Also: the objc "Class … is implemented in both Stats.framework and scarf.debug.dylib/scarfTests" duplicate-class warnings at host launch (the Stats package is linked three ways) are pre-existing and worth removing regardless.

Also fix in `scripts/ui-gate.sh`: after a host relaunch, the summary's "Test run with N tests" line is the LAST host segment's total (it printed "173 tests in 23 suites" for a 1442-test run); read the xcresult summary (`xcrun xcresulttool get test-results summary`) instead, which is what this diagnosis used.
