## Description

Dogfood findings (2 rounds): Hermes rejects <64K-context models at session/new AND session/set_model with opaque ACP -32603 (real message only in error.data.details). Round 2 proved the override path is a trap: with model.context_length set, preflight passes but Hermes's RUNTIME check measures what Ollama actually serves (qwen2.5:14b = 32,768 hard GGUF ceiling) and halts the turn with a warning instead of answering. So the picker must treat <64K reported context as effectively BLOCKED for Hermes (badge + explain), not merely warn: enumerate per-model context via ollama /api/show (model_info *.context_length), surface it in the row subtitle, and gate/sort models below 64,000. Suggest known-good models (llama3.1+ family, 131072 metadata) in the empty/blocked state copy. ALSO: model.context_length is now another local-managed key OUTSIDE LocalModelConfigPlan's clear-on-switch set — a stale override survives provider switches and masks the preflight for the next model; add it to the managed key set (clear on switch unless the new selection writes it). And surface error.data.details first-class in the ACP error banner (both the chat banner and the "Couldn't switch model" toast).
