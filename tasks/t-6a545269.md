## Description

GPTLiveEngine.exchangeOffer (GPTLiveEngine.swift ~337-370): the exchange task drops the answer when the epoch moved or the phase left .connecting (user pressed End, or connectTimeout fired, during the up-to-45 s host exchange). By then the host script may already have POSTed the offer and OpenAI has created the session, but no data channel ever opens so `session.close` is never sent. Same when applyAnswer throws after meter.start(). The type doc admits it; the test anAnswerThatArrivesAfterEndIsNeverApplied pins the drop, not the vendor side. Options: (a) add a `close` op to the host python shim that can end a session by id out of band (check whether Hermes tools/voice_live.py at the target tag exposes one; C2 cite); (b) on a late answer for a dead epoch, apply it, wait for channelOpen, send close, then tear down. Whether an unconnected session bills is unverified; check during Alan's first keyed live test.
