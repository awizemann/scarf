## Description

Found by code reading during the v3.8.0 review-droplet check; not reproduced with a read failure on a configured account. `passModelPreflight` ("scarf/Scarf iOS/Chat/ChatView.swift" ~2059) falls back to `.empty` when every config read fails, so a read failure looks like "No model is configured on this server yet", and saving from that sheet writes to the server's config. Report a failed read as a failure instead. Check whether the Mac app has the same fallback.
