## Description

Final-audit finding F1 (documents/upstream/2026-09-21-final-surface-audit-scarf.md). The P6 fix assumed a nil cost_status means a pre-v0.7 host. Wrong: Hermes only writes cost_status from update_token_counts (v2026.9.21 hermes_state_usage.py:275, COALESCE at :37), so a session that never completed a priced turn keeps it NULL on a CURRENT host. Orchestrator verified live: 9 of 43 sessions (6 acp, 2 cron, 1 telegram) have NULL cost_status; they land in .legacy and SessionsView still shows "$0.00".

Fix: distinguish "column absent" (older host → .legacy, byte-identical, C1) from "column present but NULL with no amount" (→ .unknown). HermesSession needs to know whether the cost_status column existed in the SELECT (hasV07Schema); pick the smallest honest carrier (e.g. an optional Bool on the model set by the decoder in both the local and remote backends). Fix the six comment sites that repeat the wrong framing, the :274→:275 citation nit, and the unlocalized "$0.00" in .legacy only if it can be done without changing older-host output. Add a test with a NULL status on a v0.7+ row; keep the C1 test. Also add a test for InsightsViewModel.unknownCostSessionCount (none exists). Branch fix/nil-cost-status; no push.
