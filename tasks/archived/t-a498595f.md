## Per finding

- **HIGH · `plugins install --enable` is a sixth `save_config` door** — FIXED both ways per decision 1. Lock: `PluginsViewModel` reads the P39 `.managed` probe on `load()`'s detached hop, one banner, Enable/Disable + the install sheet's enable toggle read-only, `enable`/`disable` refusing locally. Scoped to ACTIVATION only — install/update/remove write the plugin directory, which `is_managed()` never guards (the P39c rule). Verdict fallthrough for the env-var-only host: `configWriteRefusal` before `parse`'s `enabled`, so a refused enable never reports "Installed and enabled". The install sheet toggle's BINDING reads `false` while locked, because a `.disabled` toggle keeps the value it held and this one defaults to on.
- **MED · `auth logout` two exit-0 arms** — FIXED, decision 2. `HermesAuthLogoutVerdict`; both idle arms are a success with `nothingToClearNote`, the gateway "nothing was running" shape. Walked at v2026.6.19 / v2026.7.30 / v2026.8.19 / v2026.9.7 — byte-identical (C1).
- **LOW · `sessions optimize` exit-0 failure arm** — FIXED. `HermesSessionsOptimizeVerdict`, judged on `Optimized ` (`sessions_cmd.py:817`); the trailing space separates it from the in-progress `Optimizing session store …` (`:811`) every run prints first. The failure branch stopped quoting "(exit 0)".
- **LOW · `memory reset --yes` "Nothing to reset"** — FIXED, decision 3, on BOTH platforms (`MemoryView`, iOS `MemoryListView`). Success with `nothingToResetNote`; the iOS alert no longer claims the two files "were cleared" over a run that found none.
- **LOW · missing `--` before positionals** — FIXED at every listed site. Each parser opened at v2026.9.7 and confirmed a plain positional with no `nargs=REMAINDER`: `sessions rename` (`subcommands/sessions.py:210-213`), `sessions delete` (`:100-102`), `auth logout` (`subcommands/auth.py:59-61`), `auth reset` (`:40-45`), `webhook remove` (`subcommands/webhook.py:42-43`), `webhook test` (`:45-48`). `ChatViewModel` was the only rename site without the separator; both rename sites and both delete sites now share one argv builder, with the flag first and the separator after it.
- **LOW · stale iOS `skills update --yes` doc** — FIXED (doc only; the code was always right — `SkillsViewModel.updateAllArgs`).
