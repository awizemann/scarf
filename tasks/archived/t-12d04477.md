## Description

Round-4 P43c fixed this in ScarfCore (`Process.waitDrainingAsync` + a source sweep, `ProcessAsyncWaitP43cTests`), but scoped itself to the package. The Mac app target has the same shape in five places, and every one of them is reached from a `Task.detached` closure — which runs on the SAME cooperative pool the caller was on, so the block is not moved, only relabelled. The pool is one thread per core and cannot grow.

Sites (enclosing async entry in brackets):

- `scarf/scarf/Core/Services/ProjectTemplateService.swift:466` — `runToolCapturingOutput`, under `enforceArchiveBounds` ← `inspect(zipPath:)` [`TemplateInstallerViewModel.swift:117`, inside `Task.detached`]
- `scarf/scarf/Core/Services/ProjectTemplateService.swift:525` — `unzip(zipPath:intoDir:)` ← `inspect(zipPath:)` [same]
- `scarf/scarf/Core/Services/ProjectTemplateExporter.swift:383` — `zip(stagingDir:outputPath:)` ← `export(inputs:outputZipPath:)` [`TemplateExporterViewModel.swift:79`, inside `Task.detached`]
- `scarf/scarf/Core/Services/AppRelauncher.swift:105` — `relaunch()`, a 20 s budget [`ProfilesViewModel.swift:107`, inside `Task.detached`]
- `scarf/scarf/Features/Health/ViewModels/HealthViewModel.swift:1266` — `dashboardListenerPID(port:)` [`HealthViewModel.swift:1216`, inside `Task { await Task.detached { … } }`]
- `scarf/scarf/Core/Services/HermesFileService.swift:2647` — `runShellProbe`, 5 s + 3 s; check whether its callers are async.

The fix is the one ScarfCore already has: make the enclosing helper `async` and call `proc.waitDrainingAsync(…)`, which parks a DEDICATED thread (`Thread.detachNewThread`) rather than a pooled one. Then extend `ProcessAsyncWaitP43cTests.blockingCallsInAsyncFunctions` over `scarf/scarf/` as a second sweep root — the matcher is already written and calibrated — and add the `Task.detached { … }` closure shape to it, which the declaration-scoped walk does not see today.

Note the related P43c finding while you are in there: `ProcessPipeDrain`'s readers moved from `DispatchQueue.global(qos: .utility)` to a thread each, because a fixed-width pool full of blocked `readDataToEndOfFile` calls leaves the NEXT spawn's drain unscheduled — which re-enters the very pipe deadlock the file exists to prevent. That change alone removed a long-standing `swift test` flake (`ProcessDrainP43Tests.pumpSurvivesAChattyChild`).

## Artifacts

Closed by P48 (`t-86311c5a`), commit `33953111` on `fix/whole-surface-audit-r5`.

Five of the six sites are `async` on `waitDrainingAsync` now, together with the enclosing chain: `ProjectTemplateService.runToolCapturingOutput` / `unzip` / `enforceArchiveBounds` / `inspect`, `ProjectTemplateExporter.zip` / `export`, `AppRelauncher.relaunch` (20 s budget), `HealthViewModel.dashboardListenerPID`. Test callers of the template chain gained `await`; two `SpawnDisciplineP43Tests` assertions that pinned the old synchronous spellings were corrected rather than exempted.

**`HermesFileService.runShellProbe` stays synchronous, deliberately, with the reason in the source**: its only caller is the `enrichedShellEnv` `static let` initializer, which Swift cannot make `async`; the budgets are 5 s and 3 s (not the 300 s the rule was written for) and the value is computed once per process.

`ProcessAsyncWaitP43cTests` was widened as asked — `scarf/scarf` as a second root, the `Task.detached { … }` / `Task { … }` closure shape, and one level of synchronous indirection within a file — with six new calibration cases and honest per-root premise floors. Its allowlist is EMPTY and states why rather than carrying an entry for `runShellProbe`: the sweep reads `func` declarations, not property initializers, so no rule matches that site.

The widening immediately reported eleven live sites, most of them created by P48's own earlier commits (every `waitUntilExit(timeout: 0)` escalation sitting in a `Task` closure across both transports, `SSHScriptRunner` and `TestConnectionProbe`), plus `SpotifyAuthFlow.reapDetached` — the site P43c had named as the shape to NOT copy. A new `Process.waitUntilExitAsync(timeout:)` carries the ones with no drain; `reapDetached` moved from `Task.detached` to a thread.
