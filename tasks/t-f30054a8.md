## Description

Found by P51's lesson-5 sweep while fixing the two `enrichedEnvironment()` calls its task named (`EmbeddedSetupTerminal.swift:73`, `NousAuthFlow.swift:94`, both fixed in `c93c2287` on `fix/whole-surface-audit-r5`).

`HermesFileService.enrichedEnvironment()` reads a `static let` backed by two `zsh` probes at 5 s + 3 s (`HermesFileService.swift:2468-2484`). `scarfApp.swift:89-91` warms it on a detached task at launch, but a `static let` initialiser is a `swift_once`: a main-actor reader arriving while the warm-up is still running BLOCKS on it, for up to eight seconds of frozen window (C10). Five sites still do exactly that, each inside a `@MainActor` type:

- **`scarf/scarf/Core/Services/SpotifyAuthFlow.swift:133`**, inside `start()` (`:110`). This is the LITERAL idle twin of the `NousAuthFlow.start()` fix P51 just landed — same file shape, same device-code flow, same `var env = HermesFileService.enrichedEnvironment()` + `proc.run()` on the main actor. Take the same shape: a `startTask` that resolves the environment on a detached hop, a `launch(localEnvironment:)` half back on the main actor, and `cancel()` cancelling the pending start.
- **`scarf/scarf/Features/CredentialPools/ViewModels/OAuthFlowController.swift:252`**, inside `private func defaultProcess(_:)` (`:241`). Note the seam is `typealias ProcessFactory = @MainActor (_ args: [String]) -> Process` (`:95`), so moving this off-main means changing the factory's isolation — a bigger edit than the others, and the reason it is filed rather than folded in.
- **`scarf/scarf/Features/MCPServers/ViewModels/MCPLoginController.swift:237`**, inside `defaultProcess(_:)` (`:226`). Identical shape to the above, same `@MainActor` ProcessFactory typealias at `:36` — these two are one fix.
- **`scarf/scarf/Features/Health/ViewModels/HealthViewModel.swift:1180`**, inside `launchDashboard()` (`:1154`).
- **`scarf/scarf/Core/Services/HermesProxyService.swift:82`**, inside `start(provider:host:port:)` (`:72`).

Each also calls `proc.run()` on the main actor, which P51 left alone at the sites it did fix too (a fork/exec is fast next to an 8 s `swift_once`); decide whether that belongs in the same pass.

Deliberately out of P51's scope: its task named exactly two sites, and the addendum's lesson 5 says fix what the task names and file the rest. `MainActorSpawnDisciplineP22Tests` and `SpawnDisciplineP43Tests` are the suites that should grow to pin whichever of these move.

Checked and CLEAR in the same sweep, so a future pass need not re-walk them: every `.onAppear` in `scarf/Features/` and `Scarf iOS/` (no remaining main-actor `loadState()` / `readFile` / `loadProven` / `runHermesCLI`); `CredentialPoolsView.probeKeepalive` (`:171-181`, already detached); `HealthViewModel:193` (already `Task.detached`).
