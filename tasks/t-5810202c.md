## Artifacts

**Done.** One batched `statAll` per tick for the whole dashboard, replacing one stat + one transport construction per file-reading widget per tick (8 widgets = 8 SSH round-trips → 1).

Files:
- `scarf/scarf/Features/Projects/Views/Widgets/WidgetSignatureBatch.swift` (new) — per-tick coalescer + `WidgetSignatureScope` environment value + `filePaths(in:projectRoot:)` path collection.
- `scarf/scarf/Features/Projects/Views/ProjectCockpitView.swift` — `CockpitDashboardPanel` owns the `@State` batch and installs the scope alongside `selectedProjectRoot`.
- `MarkdownFileWidgetView` / `ImageWidgetView` / `LogTailWidgetView` — ask the batch, fall back to their own `stat` on `.unknown`. `log_tail` gained a stat-first skip it never had (it was re-spawning `tail` every tick), keyed on `(signature, lines)`.
- `scarf/scarfTests/WidgetSignatureBatchTests.swift` (new) — 10 tests.

Semantics preserved: `mtime:size` signatures byte-identical to `WidgetFileRead.signature`; `.known(nil)` (absent) still makes the widget read; `statAll` returning nil → `.unknown` → per-widget stat (old cost, never "unchanged"); read caps untouched.

Chose extending the existing statAll shape into a small view-scoped coalescer over a new service — the path set comes from the panel (which knows the whole dashboard), not from widget self-registration, so pass coverage can't depend on which widget's `.task` ran first.

Audit edges, each with a test: a changed file yields a different signature next tick; an uncovered path and a missing scope both return `.unknown` (widget stats itself) and never "unchanged"; the tick key is `(watcher stamp, path set)` so a dashboard that gains a widget mid-tick isn't answered from a stale map. iOS renders none of the file-reading widget types, and `WidgetView` is reachable only from the panel that installs the scope.

Known narrowing (documented in code + memory): whole-second `stat` means a same-second, same-size in-place rewrite is missed until the next change — the tradeoff the markdown/image widgets already made, now extended to `log_tail`.
