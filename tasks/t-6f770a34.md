## Description

Deferred from S2 (t-a2c169f0), audit LOW "exporter forwards agent schema into shared bundles".

`ProjectTemplateExporter` (scarf/scarf/Core/Services/ProjectTemplateExporter.swift:215-263, 298-311) forwards the config SCHEMA out of `<project>/.scarf/manifest.json` into the exported `.scarftemplate`. It already, deliberately and correctly, excludes the VALUES in `config.json` — so this is not a secret leak. What it does forward is agent-authored free text (field `label`, `description`, `placeholder`, `options`) from a file inside the agent-writable `.scarf/` directory, into a bundle the user then shares with other people.

Why it was deferred rather than fixed in S2: the sound fix is a UI change (surface the forwarded schema in the export preview so the user reviews what they're about to publish, and/or cap its size and field count), not a validator. S2 was a security-hardening batch working under the "re-derive trust at time of use" shape; adding an export-review surface is a design question that belongs with the export flow's own sheet.

Suggested scope:
- Show the forwarded schema (field keys + labels + descriptions) in the export preview sheet, as its own reviewable section.
- Cap forwarded schema size / field count the way `ProjectTemplateService.enforceArchiveBounds` caps the archive.
- Test: an export whose manifest schema carries an oversize or many-field block is refused or truncated with a message.
