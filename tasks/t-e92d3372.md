## Description

Out-of-phase finding from P23 (round-2 whole-surface audit).

`ToolsViewModel.loadPlatforms` sets `availablePlatforms = KnownPlatforms.all` with NO capability filtering (`scarf/scarf/Features/Tools/ViewModels/ToolsViewModel.swift:115`, and the status loop at `:96`). P23 gave most roster rows a verified `minimumVersion` and `PlatformsView` filters on `HermesToolPlatform.isVisible(on:isConfigured:)` (`scarf/scarf/Features/Platforms/Views/PlatformsView.swift:29-44`), so the two surfaces now disagree: the Tools tab still lists Photon / WhatsApp Cloud / ntfy / Buzz / LINE / SimpleX / Google Chat / Teams / Yuanbao and the ten B4 rows on hosts with no adapter for them.

Fix: filter `availablePlatforms` (and, if wanted, the `connectivity` map) through `isVisible(on: capabilities, isConfigured: configuredNames.contains(name))` — the same call `PlatformsView` makes, so a configured platform still stays listed when the version probe failed. `ToolsViewModel` has no capabilities today, so it needs the store injected or the filter pushed into the view. Add a test mirroring `HermesP23RosterAndGateTests.aV012HostIsOfferedOnlyWhatItHas`.

Not done in P23 to keep the phase to the capability/roster layer; the Tools tab's platform list is a read-only connectivity display, so the consequence is a misleading row rather than a broken action.
