## Description

Found by P51's lesson-5 sweep for the trim shape round-5 decision 14 fixed in `HermesYAML` (`76206b4d` on `fix/whole-surface-audit-r5`), and EXTENDED by P51b's review, which found the original sweep incomplete. **P57 appends a second, related class at the bottom.**

`HermesYAML` now trims with a space+tab `yamlWhitespace` set, because PyYAML's scanner keeps U+00A0, U+3000, U+2009, U+1680, U+202F, U+205F and U+2000..U+200A as ordinary scalar/key/entry CONTENT (verified against PyYAML 6.0.3; the oracle is pinned in `HermesP51Tests.PyYAMLWhitespaceOracleP51Tests`). Five other YAML readers still use Foundation's `.whitespaces`, which is `Zs` + tab, and have the same class of bug — a value Hermes wrote reads back SHORT, and the next save persists the trimmed form:

- **`scarf/Packages/ScarfCore/Sources/ScarfCore/Services/GatewayConfigWriter.swift`** — `:502` (the line scan), `:594`, `:641`, `:644-645` (the flow-pair scanners). This is the same file whose three flow scanners already carry an open quote-escape gap as `t-38ae4f26`; the two are naturally one pass.
- **`scarf/Packages/ScarfCore/Sources/ScarfCore/Parsing/ProfileRoutesYAML.swift`** — `:137`, `:190`, `:214`, `:245`, `:285`, `:288`, `:297`, `:313`, `:315`, `:364`. `profile_routes` entries are Scarf-written through `YAMLScalar.quoteIfNeeded`, so a route field carrying a U+00A0 is quoted on the way out and trimmed on the way back — the round trip is lossy in the direction that silently rewrites the user's file.
- **`scarf/Packages/ScarfCore/Sources/ScarfCore/Parsing/HermesBotProfileYAML.swift`** (P51b) — twenty sites: `:116`, `:118`, `:155`, `:171-172`, `:330`, `:542`, `:565`, `:590`, `:606`, `:608`, `:628`, `:635`, `:637`, `:671`, `:678`, `:699`, `:703`, `:709`, `:742`. **The riskiest of the five and the reason it was not swept in P51b:** this file is a reader AND a SURGICAL WRITER of `profile.yaml` (it rewrites lines in place), so a changed trim moves what the writer considers the key/value span, not just what a reader reports. It needs its own before/after round-trip fixtures, and the P51 PyYAML oracle extended to the block-scalar / continuation-fold shapes at `:671-709` before the swap.
- **`scarf/Packages/ScarfCore/Sources/ScarfCore/Parsing/HermesBotPeersYAML.swift`** (P51b) — `:53`, `:55`. Plain value trims on parsed entries; mechanical.
- **`scarf/Packages/ScarfCore/Sources/ScarfCore/Parsing/SkillFrontmatterParser.swift`** (P51b) — `:31`. Markdown frontmatter is YAML; mechanical.

All five should adopt `HermesYAML.yamlWhitespace` (make it `public` or `package`, it is currently internal to ScarfCore and every caller is in-package), NOT a private copy — the point of decision 14 is one rule.

Deliberately out of P51's scope: its task named `HermesYAML.swift` for decision 14. Deliberately out of P51b's scope: the bot-profile file's write-back risk, above.

Checked and CLEAR in the same sweep: `HermesEnvService` (`.env` is dotenv, a different format with its own rules, and no finding stands against it); `HermesFileService:498`, `:2729`, `:2790`, `:963` (`.env` scans, a `api_key:` presence heuristic and a CLI-output scan — none of them a config.yaml VALUE read); every remaining `.whitespaces` hit in the app target is a WRITER-side trim of a user-typed field, which P41b established is correct.

**NOT on this list, and deliberately (P51b finding 7):** `PowerSettingsWriter.swift:249` (`setReasoningOverrides`) and `:337` (`setExcludedProviders`) trim with `.whitespaces`, and they stay wide. They are WRITER-side cleanups of a user-typed field, not parser trims: Hermes compares an override key EXACTLY (`variant in overrides`, `hermes_constants.py:929-941` @ `v2026.9.7`, over `_canonical_model_variants` at `:892-926`, which never strips), so a pattern pasted with a trailing U+00A0 that Scarf did NOT trim would be written quoted and match no model for the life of the entry. Narrowing the trim would create dead overrides, not prevent them.

## P57's lesson-5 sweep — bool-word comparisons on an un-stripped scalar

P57 grepped `scarf/scarf/`, `scarf/Packages/ScarfCore/`, `scarf/Packages/ScarfIOS/` and `scarf/Scarf iOS/` for every reader comparing a scalar to `true`/`false`/`yes`/`no`/`on`/`off`. Hermes's `_bool_token` is `str(value).strip().lower()` (`gateway/config.py:29-32` @ `v2026.9.7`), i.e. the strip runs on the STRING PyYAML loaded — for a quoted scalar, on the quoted BODY.

**Fixed in P57** (all on Scarf's write path, each with a failing-first test and a PyYAML 6.0.3 oracle fixture):
- `HermesYAML.boolishValue` — trim moved after unquoting, plus a `pyYAMLIntBoolToken` pass.
- `HermesConfig+YAML.boolTrueDefault` — now calls `boolishValue`.
- `HermesConfig+YAML.busyAckEnabled` — `strippedScalar`, keeping its narrower word set.
- `HermesConfig+YAML` line ~770, the `gateway_restart_notification` copy of `boolTrueDefault`'s rule — now calls `boolishValue`.

**Left open, for whoever takes this task** (neither is on a config.yaml write path Scarf owns, so neither was fixed here):
- `scarf/scarf/Features/MCPServers/ViewModels/MCPServerEditorViewModel.swift:116-121` (`boolishSSLVerify`) — trims the RAW scalar with `.whitespaces` (the Zs class above) and never unquotes, which for `ssl_verify` is DELIBERATE: a quoted `"true"` is a CA-bundle path named `true`, mirrored by the writer at `scarf/scarf/Core/Services/HermesFileService.swift:753`. So only the `.whitespaces`→`yamlWhitespace` half applies here; do not add an unquote.
- `scarf/Packages/ScarfCore/Sources/ScarfCore/ViewModels/RichChatViewModel.swift:1299` (`nonVisionHintSuppressedByConfig`) — already strips AFTER `stripYAMLQuotes`, so the trim half is correct; it has no int-resolver pass, so a bare `model.supports_vision: 01` reads as not-set. Read-only hint suppression, no write, LOW.

**Checked and CLEAR in P57's sweep:** `HermesFileService.boolishOptional` (`:2370` — strips after unquote AND carries the `_parse_boolish` type gate); `HermesManagedInstall.system(fromMarker:)` (`:93` — a marker file's contents, already stripped); `ProfileRoutesYAML` and `Scarf iOS/Settings/SettingEditorSheet.swift:313` (both delegate to `boolishValue` and inherited the fix); `HermesFileService:753` and every other hit in the app target (writer-side typed fields, correct per P41b); `HermesServiceTier`, `HermesApprovalMode`, `PowerSettingsWriter` (not bool-word compares).
