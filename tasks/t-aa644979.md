## Description

Follow-up to #142. Hermes's `kanban_create` tool falls back to os.environ HERMES_TENANT when no tenant is passed (tools/kanban_tools.py:1055, schema kanban_tools_schemas.py:406 @ v0.21.4 canary); the CLI `hermes kanban create --tenant` has no such default (kanban_parser.py:84). Setting HERMES_TENANT on project-scoped `hermes acp` spawns (alongside HERMES_ENVIRONMENT_HINT, same plumbing: EnvironmentHintComposer / makeProcess environmentHint) would put tool-created tasks on the project's board even when the agent forgets. Before doing it: (1) find the release that added the fallback (capability flag, C1/C2); (2) check side effects — Hermes sets HERMES_TENANT for Kanban workers (hermes_cli/kanban_db_dispatch.py:2820) and workers namespace memory writes by it; confirm a chat with it set doesn't change memory/other behaviour; (3) don't clobber a user-set value. Memory: architecture/project-get-exposes-kanbantenant-and-cronnameprefix-via.
