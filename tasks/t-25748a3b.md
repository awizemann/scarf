## Description

Noticed in P44's fresh-eyes pass (pre-existing, not a P44 regression).

`_handle_slash_command` lowercases before dispatch: `cmd = parts[0].lstrip("/").lower()` (`acp_adapter/commands.py:88-91` @ v2026.9.7). Scarf does not — `RichChatViewModel.parseSlashName` and `isNonInterruptiveSlash` (`scarf/Packages/ScarfCore/Sources/ScarfCore/ViewModels/RichChatViewModel.swift`) compare the name verbatim.

Consequence: a user typing `/Queue summarize` or `/Steer be careful` on a v0.13+ host gets Hermes's real dispatch but none of Scarf's mirrors — no queue chip, no transient hint, and (since P44) the ordinary working indicator for a turn that is not actually running. The failure is conservative in every direction today, which is why it is LOW, but it is a real divergence between Scarf's model of the roster and the adapter's.

Also check `clientSideSlashCommand(for:)` (the `/new` intercept) and `expandIfProjectScoped` for the same shape; project-scoped command names are Scarf's own vocabulary so they may legitimately stay case-sensitive — decide per surface rather than lowercasing everything.

Fix: normalise the parsed name the way Hermes does, at `parseSlashName`, and add a case-mixed arm to `M9SlashCommandTests` / `HermesP44Tests.TypedSubFloorSlashP44Tests`.
