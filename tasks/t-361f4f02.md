## Description

Verified on Hermes v0.22.5: loading an adopted CLI session with a different existing folder SUCCEEDS but the gateway moves the session's workspace (rewrites sessions.cwd) — Scarf sends the project path or $HOME, so reopening a CLI chat outside a project silently re-homes it. A nonexistent folder fails with -32603 details invalid_params → error banner. Release blocker for v3.7.0: reopen in the session's own cwd, retry with default on invalid_params, then fall back.
