When a batch lands, widen `blockingCallsDoNotRideTaskDetached`'s `blockingNeedles` to cover the newly-converted calls so they cannot come back.

## Round-7 P60 — needles 12 → 15, baseline 38 → **49 across 32 keys**

P60 added `runHermesCLISplit(`, `runHermesSync(`, `capabilitiesSync(`. The reason they were
invisible is the needle boundary itself: **`runHermesCLI(` cannot match `runHermesCLISplit(`**,
because the needle's trailing `(` is a literal character and `Split` sits between the name and the
paren (`containsNeedle`). That property is what stops the two baseline keys double-counting, and it
is also what hid nine split sites in detached bodies for three rounds.

P60 converted the **three** sites that were the plain `await Task.detached { … }.value` shape —
`CuratorService.status()`, `CuratorService.runHermes` (the single seam every `curator` verb funnels
through), and `IOSSettingsViewModel`'s managed-install probe — with timeouts unchanged.

**The eleven added to this task's baseline:**

| site | needle | count | why it is not a one-line wrap |
| --- | --- | --- | --- |
| `SettingsViewModel.swift` | `runHermesCLISplit(` | 2 | `approvals suggest --json` and `--apply <n>`; the apply body also calls `svc.loadConfig()` between the CLI and the main-actor hop |
| `SettingsViewModel.swift` | `capabilitiesSync(` | 1 | inside the four-call heavy load beside `loadConfig` / `loadGatewayState` / `readText` |
| `PluginsViewModel.swift` | `runHermesCLISplit(` | 1 | one detached body: capability probe → CLI-or-directory-walk branch → `plugins compat` |
| `PluginsViewModel.swift` | `capabilitiesSync(` | 1 | same body as above |
| `CronViewModel.swift` | `runHermesCLISplit(` | 3 | `cron runs`, `cron incidents`, `cron doctor`, each parsing before its hop |
| `PeersViewModel.swift` | `runHermesCLISplit(` | 3 | `peer dm` (600 s, the CLI's own `DM_TIMEOUT_S`), `peer run` (120 s), the run-status poll |

Every one of the eleven is a multi-statement `Task.detached` body ending in
`await MainActor.run { … }`, which `OffPool.run`'s SYNCHRONOUS closure cannot take whole: the
conversion is a split of the load (blocking half off-pool, publish half on the main actor), not a
wrap. `PeersViewModel`'s 600 s DM timeout must survive any such split.

**The generalisable rule this task now carries, learned separately by P58, P59 and P60:**
a needle must be accompanied by **every one-call wrapper of it in the tree**. When you add a
needle, grep for functions whose whole body is that call — a `Split` sibling, a `…Sync` façade, a
`ServerContext` convenience — and add each of them too. A wrapper blocks for exactly as long as the
thing it wraps, and it is invisible to the wrapped call's spelling. It is written down in
`blockingNeedles`' own doc comment as well.
