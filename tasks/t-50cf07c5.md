## What it does
- Composer: a `waveform.circle` button beside the dictation mic, rendered only when `VoiceLiveReadiness.availability` is `.ready` (C1). It is disabled while dictating or disconnected. Dictation is disabled while a session is active (`VoiceLiveComposerGate`). ChatController re-reads `voice.voice_chat_mode` off-main on each Chat appearance, and only on `hasGPTLiveVoice` hosts.
- Session sheet (`Scarf iOS/Chat/VoiceLive/VoiceLiveSessionSheet.swift`):
  - Binds to `VoiceConversationEngine`.
  - Keeps `VoiceLiveMediaHostView` mounted.
  - Shows phase, captions, mute and End (graceful), plus elapsed time, approximate cost and the $0.05/min note.
  - Outcomes are localized. Idle auto-end gets its own sentence. No-key shows setup steps (`OPENAI_API_KEY` in `~/.hermes/.env`, or `voice.gpt_live.api_key`) and "Nothing was charged".
  - Try Again and Done buttons.
  - Presents Hermes tool-permission prompts over itself via `ChatPermissionPresenter`.
- `VoiceLiveSessionModel`:
  - Mic permission via `AVAudioApplication` (the same permission P1 uses). Denied shows a composer notice with a Settings link, and nothing bills.
  - AVAudioSession is `.playAndRecord` / `.voiceChat` / `[.defaultToSpeaker, .allowBluetoothHFP]`, released on terminal phases.
  - `teardown` calls `endImmediately` inside `beginBackgroundTask` (5 s grace) on: background, Chat onDisappear (tab/server/profile switch), `vm.sessionId` change, sheet dismiss, and AVAudioSession interruption.
  - `.inactive` keeps the session, so Control Center route changes work.
- Turn host (`ChatController+VoiceTurnHost.swift`):
  - The typed and voice paths now share `startPrompt`/`runPrompt`. `promptsInFlight` is counted synchronously, and `.promptComplete` is synthesized from sendPrompt's return.
  - Bubble before the first await; `contextNotes` sent as a resource block; `VoiceTurnReply.latest`.
  - Cancel runs the cancel RPC un-awaited, then waits for the prompt's return, bounded at 10 s.
- Settings: a "Live Voice" section with a Voice chat mode picker (Chained / Live Voice) via `saveVoiceChatMode`, shown only on `hasGPTLiveVoice`. The footer covers the OpenAI key, $0.05/min, and that audio goes to OpenAI.
- Info.plist NSMicrophoneUsageDescription now covers dictation (on-device) and Live Voice (streamed to OpenAI through the user's Hermes server).

## App Store privacy note for Alan (ASC not touched)
Live Voice sends microphone audio off the device: phone → WebRTC → OpenAI, with the session minted by the user's own Hermes host on the user's own OpenAI key. Scarf and the developer never receive it. Under Apple's definition, data the developer and its partners can't access is arguably not "collected". ScarfGo already sends chat text to the user's own server without declaring it, and `PrivacyInfo.xcprivacy` still declares no collected types. If you want to be conservative, declare "Audio Data — App Functionality, not linked, not tracking" in App Privacy and the manifest. Either way, App Review notes should mention the OpenAI data flow. The usage string is now truthful.

## Audit findings
- Fixed: a `begin` suspended on the mic prompt could open a billed session after the user left Chat (teardown generation); cancel racing the hand-off (synchronous count); tool-permission sheets blocked under the voice sheet; non-localized ternary strings; hard-coded idle minutes.
- Open:
  - (a) An interruption ends the session but the sheet stays up showing "ended"; the composer notice only shows after it closes.
  - (b) `refreshVoiceChatMode` costs one SSH config read per Chat appearance on 0.21.3+ hosts.
  - (c) Docker hosts whose config.yaml is unreadable keep Live Voice hidden (reads as chained).
  - (d) Cancel only waits on prompts this controller sent; a turn started elsewhere gets the cancel but no wait.
  - (e) Two test suites swap the global `ServerContext.sshTransportFactory` and can run in parallel. Both install LocalTransport, so it's harmless today.
