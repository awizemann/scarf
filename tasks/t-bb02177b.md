## Description

`./scripts/build-detached.sh` (Release) fails at HEAD — confirmed pre-existing, reproduced with all PF work stashed:

    scarf/scarf/scarfApp.swift:151:27: error: main actor-isolated initializer
    'init(context:binaryURL:unmanageableMarker:)' cannot be called from outside
    of the actor; this is an error in the Swift 6 language mode

Debug builds and all tests pass; only Release trips it, so it went unnoticed. The call is `Task.detached(priority: .utility) { ProjectsMCPRegistrar(context: .local).ensureRegistered() }` (scarfApp.swift:150-157). `ProjectsMCPRegistrar` is `struct … : Sendable` (scarf/scarf/Core/Services/ProjectsMCPRegistrar.swift:28) — the isolation comes from a DEFAULT ARGUMENT on its init (`binaryURL` / `unmanageableMarker`), and default args inherit the enclosing declaration's main-actor isolation.

The wrong fix is hoisting the whole call onto the main actor: the registrar shells out and writes Hermes config, which is exactly the charter-C10 work that belongs off-main. The right fix is to make the init's defaults nonisolated (or evaluate them at the call site on the main actor and pass them explicitly into the detached task).

Blocks the dev-copy workflow (`build-detached.sh`) for everyone, so it's worth doing before the next release cut.

## Artifacts

Root cause: app target builds with SWIFT_DEFAULT_ACTOR_ISOLATION=MainActor; ProjectsMCPRegistrar opted out only ensureRegistered(), leaving init and its default arguments (evaluated in the caller's context) main-actor-isolated — the deliberate Task.detached call at scarfApp.swift:151 (charter C10) then fails under Release's stricter isolation diagnostics. Fix: type-level nonisolated on ProjectsMCPRegistrar and nested UnmanageableMarker (SE-0449), matching the convention SkillBootstrapService/SlashCommandBootstrapService/KeychainEnvMirror already follow.
