## What changed
1. Privacy fix (the core ask): `OnDeviceDictationAvailabilityChecking` gates `startRecording()` — dictation now refuses to record at all when on-device recognition isn't available for the current locale/device, showing `.onDeviceUnavailable`. `OnDeviceSpeechTranscriber` hard-sets `requiresOnDeviceRecognition = true` unconditionally (throws `DictationError(.onDeviceRecognitionUnsupported)` instead of relaxing it) as defense-in-depth. Info.plist strings were already truthful and needed no change.
2. AVAudioSession interruption handling: production init observes `AVAudioSession.interruptionNotification` via a `NotificationCenter.notifications(named:)` async sequence; `handleAudioSessionInterruption(began:)` (internal, directly testable) discards an in-flight recording on interruption-began and shows `.interrupted`; interruption-ended is deliberately a no-op (no auto-resume).
3. Lifecycle teardown: `handleViewDisappearing()` cancels a live recording (like drag-away-cancel) or an in-flight transcription (result dropped via `Task.isCancelled`, phase still resets to `.idle`). Wired in ChatView to `.onDisappear` (TabView switch away from Chat) and scene-phase `.background` — the opposite policy from the ACP session, which deliberately stays alive across both (documented inline to avoid future confusion).
4. Permission UX: `PushToTalkNotice.opensSystemSettings` gates a new "Settings" deep-link button on denied-permission notices (mic/speech only — restricted/MDM and on-device-unsupported have nothing there to fix).
5. Accessibility: hold-to-talk mic button now exposes an `.accessibilityActions` alternative ("Start dictating" / "Stop dictating") since VoiceOver can't reliably perform the hold+drag gesture; hint text changes to explain unavailability when the composer can't send; action is omitted (not just no-op) while disabled.
6. Temp WAV cleanup audited: all existing paths (success, transcription failure, drag-cancel via `AVAudioRecorder.deleteRecording()`, recorder-start-failure) were already correct; the new on-device-unavailable path never creates a file at all (pre-flight check runs before `makeFileURL()`), and the new cancelled-transcription path still runs the unconditional `removeItem` before checking `Task.isCancelled`.
7. Swift 6 / concurrency: kept `PushToTalkController` MainActor + `@Observable`, all new collaborator protocols `Sendable`. Found and fixed a real compile-time gotcha (see Memories below).
