## Description

Found while fixing t-281048bc. RemoteSQLiteBackend shells `sqlite3 -readonly -json` over SSH at three call sites; on a remote host whose gateway is stopped (no state.db-shm), every query fails SQLITE_CANTOPEN exactly like the local case. Fix shape: drop `-readonly` and prefix the SQL with `PRAGMA query_only=1;` so the remote sqlite3 can create the sidecar but cannot write a row (same C3 reading Alan confirmed for the local backend). Needs a remote-host test or a local ssh loopback test. Not started.

**Decision: fallback, not an unconditional `-readonly` drop.** The ticket left the choice open. It is forced: `sqlite3` *without* `-readonly` CREATES a missing database file. Dropping the flag everywhere would plant an empty `state.db` in Hermes's data dir on hosts that have none (C3) and turn "Hermes not installed" into "Hermes installed but empty" (C4 absent-vs-unreadable). The strict `-readonly` path stays primary; the relaxed form is entered only after a real CANTOPEN, carries a shell `[ ! -f path ]` guard reproducing the same `unable to open database file` text `HermesDataService.humanize` keys off, and latches so a stopped-gateway host pays the doomed strict round-trip once rather than per query. A retry that also fails returns the ORIGINAL strict result, so `BackendError.sqlite(exitCode:stderr:)` never gets masked by fallback noise.

**CLI verification (sqlite 3.54.0, WAL fixture with `-shm`/`-wal` deleted)**
```
sqlite3 -readonly -json state.db "SELECT * FROM t;"
  → Parse error ...: unable to open database file (14)   exit 1
sqlite3 -json state.db "PRAGMA query_only=1; SELECT * FROM t;"
  → [{"a":1}]                                            exit 0   (state.db-shm/-wal created)
sqlite3 -json state.db "PRAGMA query_only=1; INSERT INTO t VALUES(2);"
  → Error ...: attempt to write a readonly database      exit 1
sqlite3 -readonly -json missing.db "SELECT 1;"
  → unable to open database file   exit 1   file NOT created
sqlite3 -json missing.db "PRAGMA query_only=1; SELECT 1;"
  → [{"1":1}]                      exit 0   file CREATED   ← why the guard exists
```
Same results through the heredoc/stdin form the backend actually uses.
