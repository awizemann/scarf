## Description

Noticed during P13 (t-8d2a8e04). `HermesConfig+YAML.swift`'s `gatewayAllowlistPlatforms` loop reads `<platform>.busy_ack_enabled` and the parse comment already says it is "a no-op per-platform (Hermes reads only the global `display.busy_ack_enabled`)". Re-verify at v2026.9.7: a whole-tree `git grep busy_ack_enabled v2026.9.7` returns only `gateway/run.py:1813` (the `_DISPLAY_ENV_BRIDGE` entry for the GLOBAL key), `gateway/run_busy.py:727` (`os.environ.get("HERMES_GATEWAY_BUSY_ACK_ENABLED", "true").lower() != "true"`) and the website docs — no per-platform read anywhere. If it is genuinely dead at every supported tag, drop the field and its round-trip rather than keeping a toggle that saves a key nothing reads; if some tag DID read it, record the window.

Also worth noting while there: the global key's reader compares the bridged string against `"true"` exactly, so `display.busy_ack_enabled: 1` reads OFF on the host while Scarf's `boolTrueDefault` reads it ON. Every other spelling agrees (PyYAML turns bare `yes`/`on` into True -> `"True"` -> ON). Decide whether that one edge is worth a bespoke reader or a documented divergence.
