## Description

Pre-existing (found in the v0.21.1 Phase 3 cron pass; out of that phase's scope).

`CronViewModel.createJobArguments` appends argparse's `--` end-of-options marker before the `schedule` / `prompt` positionals, because a prompt that legitimately opens with a dash ("--deliver isn't working, investigate") is otherwise claimed as an option and the create dies at exit 2.

Two other cron-create argv builders do NOT:
- `scarf/Packages/ScarfCore/Sources/ScarfCore/Services/FleetApplyPlan.swift:399-401` (`cronCreateArgs`) — appends `schedule.argumentValue` then the rewritten prompt with no marker. Reached by fleet-apply copying a job whose prompt starts with a dash.
- `scarf/scarf/Core/Services/ProjectTemplateInstaller.swift` `createCronJobs` — same shape (`args.append(job.schedule)` then the resolved prompt). A template author's prompt starting with a dash aborts the WHOLE install (the create failure throws).

Fix: append `["--"]` immediately before the positionals in both, after every flag (argparse treats every token after the first `--` as positional, so it must come last). Add a test in each builder's existing suite pinning a dash-leading prompt.
