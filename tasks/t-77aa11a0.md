### Deliberate NO-OPs
- **`computer-use doctor --json` is not consumed.** Its payload is documented as "the raw structured payload (same shape as `tools/call`)" — cua-driver's, not Hermes's, so it has no stable contract to fixture. `permissions status --json` folds the same doctor matrix into a normalized payload with a documented key order, so the card reads that instead.
- **`trust_level` is parsed but not modelled** in the hub row — the Hub UI shows source, not trust tier, exactly as the table path did. Out of scope to add a column.
- **No `--nous` / `--no-redact` surface** for debug share. Both change what leaves the machine; neither was in scope.
- **`plugins compat <path>`** (the plugin-author scan-one-directory form) is not surfaced — Scarf's Plugins pane is about the installed set.
- **pbxproj left untouched** — the test files land via the synchronized folder; an Xcode-reordered pbxproj diff was reverted as unrelated noise.

### Fresh-eyes audit
1. *The C8 floor was wrong in the Phase-0 flag comment.* `hasComputerUseDoctorJSON`'s doc asserted v2026.8.31 "has no `json` reference at all" — true only because the module didn't exist. Corrected in place, and the sibling `permissions status` surface got its own v0.18 flag rather than riding the wrong floor.
2. *C1 vs. a true floor below the target.* Gating a v0.18 surface at v0.21.1 would hide something the host has — the exact failure `hasKeenableWebBackend` hit last phase. Resolved in favour of the true floor; reasoning recorded in the decisions note.
3. *`-y` on a pre-v0.18 host would be an argparse error* that breaks a command which previously worked. The gate omits it there, and there is a test for that direction specifically.
4. *nil vs empty on both new parsers.* Rendering "no affected plugins" / "driver not installed" over a command that never ran is the worst outcome for a warning surface; both parsers return nil without a payload and both callers hide rather than claim.
5. *Stale compat report after a mutation* — checked: every `enable`/`disable`/`update`/`remove`/`install` path already calls `load(force: true)`, which re-runs the compat probe.
6. *Subprocess bounds (C10)* — the compat call is 45 s and rides the existing detached roster hop; the computer-use probe is an explicit 45 s (cua-driver's own probes cap near 27 s internally) and joins Health's existing concurrent `async let` fan-out, so it costs no extra round-trip wall time.
7. *Known residual (accepted):* the compat banner lives inside `list`, so a host whose plugin roster failed to load renders the empty state instead of the banner. `plugins compat` only reports ENABLED external plugins, which by construction appear in the roster, so the window requires the roster read to fail while the compat read succeeds.
