## Description

Proven pre-existing during P54 (round-6 lesson 8: "pre-existing" needs proof — a failing test is pre-existing only when it reproduces on a `main` worktree).

Two ScarfCore tests assert wall-clock elapsed time and fail intermittently on a full parallel `swift test`, while passing 100% in isolation:

- `ProcessDrainP43Tests` → "backup's zip refuses instead of hanging when it outstays its budget" (`ProcessDrainP43Tests.swift:208`, `#expect(elapsed < 8)`)
- `OffPoolP52Tests` → "N blocking calls do not queue behind one another" (`OffPoolP52Tests.swift:74`, `#expect(allArrived)`)

Evidence: a `git worktree` at `main` (`d53d3cbe`) reproduced them in **3 of 5** full `swift test` runs, with the same two names and the same assertions. Both pass in isolation on both `main` and `fix/whole-surface-audit-r6` (`swift test --filter 'ProcessDrainP43Tests|OffPoolP52Tests'`, 17/17 and 6/6).

Cause is the shape, not the code under test: both measure a deadline against real time while ~3100 other tests compete for cores, and `OffPoolP52Tests` additionally races N threads reaching a barrier. Adding tests to the suite makes them flake more often — which is a bad property for a suite that only grows.

Fix direction: give both a generous CI-aware ceiling (an env-var multiplier, or read `ProcessInfo.activeProcessorCount`), or convert the OffPool one from a wall-clock barrier to a semaphore with a long timeout that proves the SHAPE (N threads, not one) without timing it. Related known flake: `ACPClientStartIdempotenceTests` (`t-f3820038`).
