## Description

P46b closed this for `gateway_restart_notification` on slack/telegram only. The general hazard stands.

**The walk** (`v2026.9.7`): `platform_section` (`gateway/config_loader.py:171-180`) picks ONE section to bridge a platform's `_SHARED_KEYS` from — a top-level `<name>:` block WINS over `gateway.platforms.<p>` / `platforms.<p>`; `bridge_platform_shared_keys` (`:249-283`) then copies only that section's shared keys into `extra`. So on a nested-only host, ANY write that creates a bare top-level `<platform>:` block silently un-bridges every `platforms.<platform>.<shared key>` the user already has — a setting nobody touched, turned off by a write to an unrelated key.

**Scarf's writes that do it:**
- `TelegramSetupViewModel` sends bare `telegram.reactions` and `telegram.disable_topic_auto_rename` (not shared, so `HermesPlatformSharedKeys.resolved` leaves them alone) — this is the case P46 documented on `HermesPlatformSharedKeys.resolved` and did not close.
- `GatewayConfigWriter.saveList` (step 1 of `GatewayBehaviorViewModel.save`, `scarf/scarf/Features/Platforms/ViewModels/PlatformSetup/GatewayBehaviorViewModel.swift:181-192`) writes `<platform>.allowed_channels` / `allowed_chats` / `allowed_rooms` by DIRECT YAML edit — outside the `config set` path `resolved()` guards entirely. `allowed_chats` is itself a `_SHARED_KEYS` member.
- Every other setup form's bare `<platform>.<unshared>` key.

**Why it wasn't closed in P46b:** closing it means either writing the unshared keys nested too (each has its own hard-coded reader in `HermesConfig+YAML.swift`, so the read and the write must move in the same commit — the honest-half rule `bridgeResolvedKeys` exists to enforce), or seeding the newly-created block with the shared values it displaces. Both are bigger than a remediation splice.

**Files:** `scarf/Packages/ScarfCore/Sources/ScarfCore/Parsing/HermesPlatformSharedKeys.swift` (the hazard is documented on the type, "The hazard this type does NOT close"), `scarf/Packages/ScarfCore/Sources/ScarfCore/Parsing/HermesConfig+YAML.swift` (the hard-coded readers), `scarf/scarf/Features/Platforms/ViewModels/PlatformSetup/`.

Related: `t-6fa3fc84` (the original shared-key write bug), `t-f3d7bdd2` (the stale shadow `resolved()` leaves behind).
