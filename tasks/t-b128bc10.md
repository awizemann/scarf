## Description

Seen once on 2026-09-19 in the full serial Mac run while two other xcodebuild runs shared the machine; 3/3 green in isolation. scarf/scarfTests/ProjectTemplateBoundsP43Tests.swift ~172: the test polls `vm.stage` for `.failed` and then immediately asserts the temp archive is gone. TemplateInstallerViewModel appears to set the stage before (or concurrently with) removing the archive, so under load the assertion runs in the gap. Fix: either make the view model remove the archive BEFORE publishing `.failed` (preferred — the state should not say "done" while cleanup is pending), or have the test poll for the file's absence with the same deadline. Add the ordering as a test.
