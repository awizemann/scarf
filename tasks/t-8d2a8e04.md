**2. Raw bool compares.** display.streaming, voice.auto_tts, display.interim_assistant_messages and the three Slack flags now go through `boolTrueDefault` / new `boolish(_:default:)` / new `boolTrueDefaultAt([keys])`. The last preserves Slack's top-level-over-`extra:` precedence on the FIRST KEY PRESENT — the old `??` chain picked the first non-nil RAW string then compared it literally, so `platforms.slack.require_mention: false` fell through to a true `extra:` value.

**3. ~20 true-default bools.** 22 sites converted to `boolTrueDefault` after checking each against DEFAULT_CONFIG at v2026.9.7 (exec'd `config_defaults.py`). **4. `strEnum()`** added and applied to all eight closed-enum keys. Normalises via `HermesYAML.normalizedScalar`; deliberately does NOT validate against a member set (Hermes grows these enums; snapping an unknown member to the default would hide a value a newer host honours and overwrite it on save). Both affected pickers instead APPEND an unrecognised stored value so the control is never blank.

**5. `ignore_root_dm` ceiling.** Confirmed by whole-tree grep at every tag: reader present from v2026.5.28 (0.15.0) `gateway/platforms/telegram.py:4879`, moved by the v0.18 plugin split to `plugins/platforms/telegram/adapter.py:9835` (last at v2026.8.31 = 0.21.0); at v2026.9.7 the string survives ONLY in `scripts/release.py:798` (contributor attribution) and the website docs — no reader in shipped code. Modelled as `hasTelegramIgnoreRootDM`, a WINDOW like `hasTavilyWebBackend`, with the standard `HermesCapabilitiesTests` pattern (both edges + patch + unknown). Unknown version KEEPS the row (C1). The parse is untouched so the value round-trips on every host; the row AND the write are windowed.

**6. mattermost `reply_mode`** now read from `platforms.mattermost.extra.reply_mode` (adapter.py:120-121 reads `config.extra` only, and `reply_mode` is not in `gateway/config_loader.py`'s `_SHARED_KEYS` :197-215, so the top-level spelling is never bridged). No UI change — the setup form edits the `MATTERMOST_REPLY_MODE` env var, which is the adapter's other source.
