## Description

Found during P41b (commit `9f23018f` on `fix/whole-surface-audit-r4`) while sweeping for the quote-scanner gap that P41b fixed in `HermesYAML.closingQuoteIndex`.

`scarf/Packages/ScarfCore/Sources/ScarfCore/Services/GatewayConfigWriter.swift` has THREE hand-rolled quote scanners that track an open quote with `if ch == q { quote = nil }` and no escape handling:

- `parseOrderedFlowPairs` (`:618`) — the entry splitter
- `flowPairSeparatorIndex` (`:660`)
- the scanner at `:881`

For a DOUBLE-quoted span a `\"` closes the quote early, so a key or value like `"a\"b: c"` has its separator found INSIDE the key (the same defect P41b fixed in `HermesYAML`). None of them skips `''` for single quotes either, though there an even number of quotes happens to cancel out for separator-finding.

Out of P41b's scope deliberately: P41b's finding 4 named `HermesYAML`/`HermesFileService`, and these scanners parse the gateway platform allowlists (`allowed_channels` / `allowed_chats` / `allowed_rooms`), whose writer is `GatewayConfigWriter.saveList` through `yamlQuoteIfNeeded`. Worth deciding whether they should route through the same `HermesYAML` primitives (there is no flow-mapping equivalent of `blockKeySpan` yet), and shipping the fix with a test that fails without it.
