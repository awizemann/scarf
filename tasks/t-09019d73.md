## Description

P8 audit SEC H1/H2/M1/M3: apply ProjectRootPolicy at registry load / uninstall plan build (agent can edit projects.json directly, re-opening the S1 HIGH through the root), make it symlink/firmlink-aware; replace the 32-bit FNV-1a path-hash Keychain binding (chosen-preimage in milliseconds) with truncated SHA-256 or owning-project-UUID stored in the item; scheme-handler/bridge reads via O_NOFOLLOW + fd validation to close the symlink-flip TOCTOU.

## Plan

Done (T1). Three fixes, one theme: nothing an agent can write is a record of what Scarf did.

1. SEC-H1/M3 — ProjectRootPolicy applied at TIME OF USE and made physical.
   - `refusalAtUse(for:context:)`; candidate judged in every spelling
     (literal → physical → /private and /System/Volumes/Data variants),
     refusal wrapped as `.resolvesTo` when found in a resolved spelling.
     Remote roots: universal rules only (no realpath over ServerTransport).
   - Applied at: uninstall plan build (plan does nothing, reason leads
     refusedEntries, new `rootRefused` zeroes totalRemoveCount), uninstall
     execute (throws `.inadmissibleProjectRoot` before the first deletion),
     WidgetPathResolver (`.inadmissibleRoot`), MiniAppSchemeHandler (403,
     computed once at mount), ScarfMiniAppBridge file.read.
   - DECISION: refuse the ACT, never drop the row from the sidebar.

2. SEC-H2 — Keychain binding is now truncated SHA-256 over
   (template slug, project path), service bound via the same digest.
   Legacy 8-hex FNV accepted on READ only; `make` mints only the new form.
   Uninstall queues the derived modern account alongside a legacy lock
   entry so a re-minted secret isn't left behind.

3. SEC-M1 — `MiniAppAssetResolver.readContainedFile`/`readValidated`:
   one fd, O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC, fstat regular-file + cap,
   F_GETPATH containment recheck, read to EOF. Never re-opens the path.
   Locality is a precondition (`isLocal`), which also fixed a latent bug
   where file.read served local bytes for a remote project.

Tests: 22 new in ScarfCore (ProjectsT1SecurityTests, incl. a REAL FNV-1a/32
collision found by meet-in-the-middle), 8 new in the app target
(ProjectsT1TrustAtUseTests). ScarfCore 2097+42 pass, scarf scheme 698 pass,
iOS builds.
