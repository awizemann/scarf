# Swift Audit — Scarf v3.8.0 (macOS 15+, iOS 18.6+, 2026-11-01)

Scope: v3.7.1..bf9e7f2b. Six specialists, code reading only: nothing was run, and costs are unmeasured. "Verified" means the lead re-read the code; the rest are as reported.

## Executive summary
No P1s: no crash, data loss or wrong-chat approval was found. The chat engine's core (budget, single-flight recovery, approval identity, stale-callback guards) came back solid. The real risks are at the edges of parallel chats: a chat stuck showing "working", SSH recovery closing a healthy shared connection (more damaging now that several chats share it), and held sends lost during teardown. Approval safety has three gaps: unmodified digit shortcuts, command text in notifications, and a project's accept_edits applied before the user's pick on re-attach. Background chats also do as much UI work as the shown one, which is unmeasured. Accessibility has one theme: VoiceOver hears no state changes. Recommendation: fix the "before the cut" list, all small, then rerun the gates.

## P2 — recommended before the cut
1. **Chat stuck on "Agent working".** `ChatSession.swift:1798,1806,1859`. Verified. A finished turn stays counted through post-processing (`settlePromptTurn` is deferred to the end), so a fast slash command returning then skips its own completion; Stop can be hidden too. Fix: settle before `promptComplete`. S.
2. **Recovery can close a healthy master unprobed.** `SSHTransport.swift:185,191`. Verified. The probe uses the default gate, unlike `-O check`; an open breaker throws, `try?` gives nil, and nil means dead, so `-O exit` runs and every chat on the host drops. Code predates v3.8.0; parallel chats raise the cost. Fix: probe with `gate: .none`. S.
3. **Wake verify can kill a fresh master.** `scarfApp.swift:1032`. Verified. Bypasses `SSHMasterRecovery`, and with a 3 s probe it can issue `-O exit` on the master a chat just rebuilt. Fix: read-only `-O check`. S.
4. **Held sends survive `stop()`.** `ChatSession.swift:1218,1236`. Verified. `beginHoldingSends` clears `holdingForPendingClient`, so `dropReconnectHeldSends` exits early. The message vanishes silently and the chat counts as working, so close and quit say "still replying". Fix: clear unconditionally in `tearDownConnection`. S.
5. **Spawn after window close or delete.** `ChatViewModel.swift:2650`, `ChatSession.swift:271`. Shape verified. Focused chat is `stop()`ped, not superseded, during a pre-spawn read, so an untracked `hermes acp` can start for a gone window. Fix: `supersede()`, `beginStartIntent()`. S.
6. **Bare digits answer approvals.** `ChatView.swift:1112`. Verified; the shortcut predates v3.8.0, but queued background approvals now surface on focus. A digit being typed, or a second press on the next card, can approve an unread command, and "3" on an edit card sets accept_edits. Fix: ignore shortcuts for 500 ms after a card appears, and key repeat. S.
7. **Command text in notifications.** `ChatViewModel.swift:2803`, `ChatNotificationService.swift:124`. New in v3.8.0. Not re-read by the lead. A raw tool title, which can hold a token, shows in banners and Notification Center. Fix: generic body by kind. S.
8. **Re-attach applies project accept_edits before the pick; failed re-send is only logged.** `ChatSession.swift:2984,1413,2520,2181`. Verified. A Default pick can silently be left in accept_edits. Fix: skip when a pick exists; raise `acpError` on failure. S.

## Clean bill
Wrong-chat approval (identity is chat plus request id; answers remove by id). Budget selection and no counter drift. Single-flight core. Quit bounded at 3 s. Bounded session cancel. Stale event loops and prompt callbacks. Window close proxy. Notification lifecycle and routes. Delete stops first, with lineage segments. Render window and settled-bubble equality. Row bodies read scalars only.
