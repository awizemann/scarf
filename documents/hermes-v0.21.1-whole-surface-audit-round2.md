## Verdict

**P9–P17 hold.** Every round-1 finding the reviewers re-derived is genuinely fixed, and the seven "Verified sound" sections are substantially larger than round 1's. No phase introduced a regression that a reviewer could demonstrate. But reading the *surrounding* surface end to end found **12 HIGH, ~50 MED, ~50 LOW** — the great majority pre-existing and newly visible, plus a handful of incomplete-fix residues where a phase applied its rule to one site and not its twin.

Defect classes, round 2:

1. **Incomplete-fix residue — the same bug class, the sibling site.** P15 fixed "empty field is a real gesture" for skills but not for `repeat` (HIGH) or `prompt`; P17 fixed `.applied`-when-nothing-written for `scriptOnlySkipped` but not for the cancelled cron pass; P10 quoted MCP scalar *values* but left map *keys* bare (HIGH); P11 detached `SettingsViewModel` and `GatewayBehaviorViewModel` but not the platform-setup VMs (HIGH); P17's "no literal `== \"true\"` reader remains" is asserted in a comment 78 lines above a surviving one; P14's dead-decode sweep left `parent_results` and eight more never-emitted wire keys.
2. **Config-read defaults that are still wrong, and wrong in the direction that misinforms.** Four HIGH: `approvals.mode` (Scarf says Manual, stock ≥0.19 host is `smart`), `memory.*` char limits parsing to `0` outside their own stepper range, `voice.auto_tts` shown ON against a False default, `memory.memory_enabled` shown off against a True default. Plus ~12 MED of the same shape (container limits, `display.show_reasoning`, `approvals.timeout`, bitwarden `override_existing`, telegram `require_mention`), and three platform *read-path* precedence bugs where Scarf reads a key Hermes never reads.
3. **YAML writer surface that can still make PyYAML reject or silently reshape config.yaml.** Unquoted `env:`/`headers:` map keys (HIGH); a duplicate-key `Dictionary(uniqueKeysWithValues:)` trap that crashes the process on Save (HIGH); a UTF-8 BOM defeating every section-header match so the first section is duplicated and clobbered; a quote-doubling writer with a non-un-doubling reader that corrupts a value a little more on every save; `yamlScalar` still with no line-break guard.
4. **Output-judged verdicts that judge the wrong thing.** `mcp login` can report a *successful* login as failure because P9's output verdict races the pipe drain (HIGH); `pairing list`'s two hint lines parse as pending pairings with live Approve buttons (HIGH); `plugins install`/`update` also discard the consent bool (HIGH) — round 1 only caught `enable`; `skills update` still judged by exit code; a success marker matched as a bare substring can outrank a real failure.
5. **Capability floors and roster gating still off — the other direction from round 1.** The `isV020OrLater` cluster was never walked: seven flags (or flag groups) floor one to four releases too high and hide working surfaces on 0.18–0.20.3 hosts; `hasCompressCommand` is inverted and sends `/compact` to hosts where that is the TUI display toggle (HIGH); the version parser has no major-component bound, so an unrecognised shape degrades **unsafely** — every write/argv gate lights up.
6. **Stale doc comments and citations (C2) — still ~20 of them**, now including several introduced or left by P14/P15/P16 themselves, and five citations past EOF of `gateway/config.py`.

## Product decisions for Alan (calls, not bugs)

These are places where the reviewers found a real divergence but the right answer is a product choice, not a defect fix. Each needs a decision before its phase can be scoped.

1. **iOS markdown rendering of worker-authored bodies.** The Mac inspector renders a kanban card body as plain `Text` deliberately ("must not diverge"); iOS renders it through `AttributedString(markdown:)`. Do we (a) drop iOS to plain text for parity, (b) keep markdown and add a scheme allowlist (`http`/`https`/`mailto` only), or (c) keep markdown everywhere and allowlist on both? `ScarfGoKanbanDetailSheet.swift:82-88`.
2. **`hermes skills audit` presented as "reload".** `do_audit` only re-runs the security scanner; the real reload is the gateway `/reload-skills` slash command, which has no CLI form. Do we relabel the button "Re-scan skills", remove it, or wire a gateway slash-command path? `SkillsViewModel.swift:608-632`.
3. **The "Redact secrets" toggle for the `trace` export format.** Trace redaction is on by default and is opted OUT with `--no-redact`; `--redact` is ignored. Do we invert the toggle's meaning for trace, disable it with an explanation, or hide it on that format? `SessionsViewModel.swift:724-730`.
4. **TTS/STT picker membership.** `gemini`/`kittentts` (TTS) and `elevenlabs`/`deepinfra` (STT) are live at target but absent from the pickers. Do we list every registered provider, or curate to the ones we're prepared to support in Settings — and if curated, what happens to a host already configured with an unlisted one (today: blank picker, silent overwrite)?
5. **`approvals.mode` default semantics.** The upstream default changed `manual`→`smart` at v0.19.0. Sentinel + capability resolution is the correct mechanism, but it means the picker shows a resolved value that depends on the detected host version, and an UNDETECTED host has no honest answer. Do we render "Host default (smart)" as a distinct row, or fall back to `manual` and label it as unknown?
6. **`whatsapp_cloud` roster gating.** `photon` is floored at 0.17 and `whatsapp_cloud` — same v0.17 adapter — is not. Do we gate `whatsapp_cloud` (and audit the rest of the roster) to hide channels a host cannot listen on, or ungate `photon` on the principle that the roster is a menu and the host's own error is the gate?
7. **Version-parser degrade direction.** `parseLine` currently degrades UNSAFELY for an unrecognised shape (a date-only `v2026.9.7` lights every write gate). The safe fix is a major-component bound, but that means a legitimate future versioning scheme would degrade to "no capabilities". Confirm we want fail-closed.
