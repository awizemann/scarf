# Projects Post-Remediation Full-Surface Audit (P8)

Date: 2026-09-04 · Branch: main @ 73b775e · Four fresh-eyes specialist audits over the ENTIRE projects surface after the P7 remediation landed (commits 926452a S1, ad9d4e9 D3, 1d6a6ec AX, 7bc27c9 D1, 78cccf7 MCP, 25420ab S2/D2, 73b775e PF). Successor to reports/2026-09-03-projects-full-surface-audit.md.

## Verdict

The P7 remediation is real and holds under attack: uninstall containment, symlink-safe removal, HMAC grant signing, transport atomic-write parity, the registry chokepoint, absent-vs-unreadable probing, and the tick decoupling all survived deliberate bypass attempts (each auditor lists the invariants they tried and failed to break). What this round found splits into two piles: (a) the same structural themes re-entered through doors the batches didn't cover — trust anchored on the agent-picked project ROOT, `fileExists` as the un-plugged absent-vs-unreadable hole, guards applied to files not writers, lock/`expecting:` applied at one call site each — and (b) a handful of defects in the new machinery itself.

## Security (0 CRITICAL, 2 HIGH, 6 MEDIUM, 5 LOW)

- **H1** ProjectRootPolicy is mint-time only: an agent editing projects.json directly sets a row's path to `/Users/me`, and every S1 containment guard passes against that root — one uninstall click deletes the home's contents again. Fix: apply the root policy at USE (registry load / plan build), not only at registration. Also M3: the policy is symlink-blind and lexical (a `~/r → /` symlink, or the `/System/Volumes/Data` firmlink spelling of home, passes).
- **H2** Cross-project Keychain isolation rests on a 32-bit FNV-1a path hash with a trivially computable chosen preimage; the service half isn't bound at all. A crafted sibling directory name collides with project B's hash and KeychainEnvMirror exfiltrates B's secret into A's env block at next launch. Fix: truncated SHA-256 and/or bind by owning project UUID stored in the item.
- **M1** mini-app scheme-handler/bridge TOCTOU (check path, open later by path — widened by the PF async hop): symlink-flipping leaks `~/.hermes/auth.json` into a web context. Fix: `O_NOFOLLOW` + fd validation. **M2** HMAC payload not injective in the permissions field (comma-joined; `query:sessions,store` re-splits to a never-approved `store` grant under the same tag). **M4** image widget is still an unconsented repeating beacon to an agent-chosen https host. **M5** the registry lock file is agent-writable — attacker-controllable DoS/removal; document as such, plus release() ownership (see DI-H4). **M6** project_set_config writes the login Keychain with an agent-chosen slug, no consent, and writes config.json unguarded.
- LOWs: ICU-lenient `$` in slash-command name regex (`deploy\n` validates); `.bak`/quarantine copies bypass TransportPrivateMode (basename match only); grants/session-map unlocked cross-process; consent sheet renders `query:<kind>` verbatim (spoofing surface); malformed lock's memory-block strip can eat MEMORY.md to EOF.
- Held under attack: S1 containment given a sane root, symlink races in removal, lock O_EXCL semantics, 0x1F HMAC separator, unsigned-grant forgery, generated-flag defaults, keychain:// smuggling, scheme-handler lexical traversal, cron argv refusal, zip bounds, env-block forgery, RemoteRestore fix, saveRegistry chokepoint.

## Data integrity (2 CRITICAL, 7 HIGH, 7 MEDIUM, 5 LOW) — theme: the D-series fixed files, not writers; `fileExists` is the hole

- **C1** `ModelPresetService.persist` is still the exact pre-D1 destroy shape: `fileExists` false on a transport blip → empty store → next upsert publishes a one-preset file over a full one. No guard, no .bak. Last of the four adjacent stores, missed by the D1 conversion.
- **C2** `ProjectContextBlock.writeBlock` replaces the user's whole AGENTS.md when `fileExists` lies (runs on EVERY chat start, Mac + iOS); a non-UTF-8 byte also collapses the file to block-only. No .bak exists for AGENTS.md anywhere.
- **H1** Citadel rename fallback deletes the destination on ANY rename error (not just EEXIST) — on a dropped link the destination is deleted and the retry fails too; gate on destination-exists and retry before touching the destination. **H2** `ScarfProject` (project.json) still drops unknown keys — the one file documented as portable lacks the preservation contract ProjectEntry/Dashboard got. **H3** MCP project_set_config rebuilds config.json from a failed read (orphaning every other keychain ref) and drops unknown top-level keys on the happy path. **H4** `RegistryWriteLock.release()` deletes whatever lock is present with no ownership check — a >30s remote save has its "stale" lock broken, then release() deletes the successor's lock and two writers run concurrently. **H5** the lock covers `indexInRegistry`'s RMW but not the doctor/installer/uninstaller RMWs, and `expecting:` is threaded from ProjectsViewModel alone — Repair All from a stale snapshot erases a concurrent project_register silently. **H6** a single misaligned SSH poll reply replaces the whole watch-baseline map with a blob signature, wiping per-path baselines and swallowing the deltas in the gap. **H7** an empty poll reply skips the sleep — tight SSH loop.
- Mediums: project.json never quarantined (contradicts GuardedJSONStore's own doc; corrupt bytes end in a one-deep .bak, gone after two saves); GuardedJSONStore backs up QUARANTINED bytes into .bak, destroying the last-known-good copy; an unavailable signing key makes the next grant write permanently purge all grants (drop-on-read is a recovery, drop-on-write is not); grants/session map have no cross-writer serialization (Mac + iPhone on one remote lose attributions); `registryBusy` reachable in normal remote use (2s bound vs 60s scp windows); statAll misattributes on newline-containing paths; quarantine dedup costs 1+2K round-trips per tick while a corrupt file exists.
- Lows: RemoteRestore writes projects.json without lock/expecting; rename against a sick transport reports success (doctor backstops); SessionProjectMap lacks `extra`; installer mints random UUID vs deterministic id; AGENTS.md block not re-rendered on rename until next chat start.
- 14 invariants verified holding, including: no registry-chokepoint bypass, Citadel happy-path atomicity, per-write SSH staging, consistent proof-based probing, single-inspection writes, zero-bytes-is-damage, lock reentrancy, value-typed mutation baselines, uuid-keyed rename/removal convergence, iOS detailed loads on both list surfaces, guarded iOS cron writes.

## Performance (3 HIGH, 5 MEDIUM, 4 LOW) — PF's claims verified: ~6/tick vs ~55-70, doctor genuinely off-tick

- **H1** `SSHTransport.statAll` zips stats to paths positionally with NO count guard (the poller 350 lines later has one): one stray stdout line shifts every signature, and the wrong answer is STABLE — the cockpit short-circuits forever until a manual refresh. **H2** the sidebar's unchanged tick still writes `@Observable` state three times (`projects`, `registryDamage`, `selectedHasDashboard`) — @Observable setters don't compare, so the whole sidebar re-evaluates per tick (O(F·N), double `folderProjects` evaluation). **H3** `refreshDashboardFlag` stats dashboard.json every tick for one glyph the cockpit's statAll already stats.
- Mediums: KanbanSummaryWidgetView.readTenant does 2 blocking SSH round-trips ON THE MAIN THREAD retried every 10s when nil (last clear C10 remnant — 60s timeout = beachball); synchronous `viewModel.load()` survives at 3 sheet-completion call sites (+ unmirror on main); corrupt registry amplifies the tick (re-quarantine per tick, 1+2K round-trips, K never pruned); statAll's all-or-nothing empty-map failure makes any blip take the full derive-and-save path over the sick transport (the exact stripped-record shape D3 closed, now deterministic); widgets each stat individually (8 widgets = 8 round-trips + 8 transport constructions per tick — statAll unused where N is largest).
- Lows: fileExists-then-readFile double probes (~4 avoidable round-trips per changed load); lock's Thread.sleep parks a cooperative-pool thread (fine today, decays silently); iOS dashboard poll compares mtime-seconds only (no size, strictly-greater); unarmedProjectPaths retries one open(2) per dashboard-less project per tick forever.
