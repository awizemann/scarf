From the P7 projects audit's Performance section (documents/reports/2026-09-03-projects-full-surface-audit.md), remediated in batch PF (t-45594d27). The theme the audit named was "everything hangs off the watcher tick": the tick fires every 0.5-1.5s during an active stream, and four separate project surfaces treated it as an instruction to reload everything they own.

## Observations
- [fact] Counted by inspection (20 projects, SSH, active chat stream): the coalesced tick cost ~54 SSH round-trips — cockpit full facet reload 11-12, menu probe 2xN = 40, sidebar registry + dashboard exists + dashboard read 3 — plus a ~110-op doctor scan every 5 minutes triggered BY a tick. After PF (t-45594d27) an unchanged tick costs ~3-4: one batched stat for the cockpit, zero for the probe cache, registry + one stat for the sidebar, zero watcher rebuild. Local FSEvents rebuild went 2N=40 open(2) per tick to 0. #performance
- [decision] The fix shape is one question asked four ways, NOT a cache layer: `transport.statAll` (new; one SSH round-trip for N paths, SSHTransport overrides the default per-path loop) answers "could the bytes differ?", and each surface short-circuits on it. ProjectCockpitViewModel keeps a path -> mtime:size map of every facet it read; ProjectMenuProbeCache skips an unchanged project set (60s revalidation + explicit invalidate on install/uninstall); HermesFileWatcher.updateProjectWatches diffs its path set; the markdown_file/image widgets stat before re-reading. #projects
- [gotcha] A change signature must pair mtime with SIZE. `stat` reports whole seconds over SSH, so mtime alone calls two writes inside one second identical — and every Scarf write is an atomic replace, exactly the shape that lands twice in a second. ABSENT must also be a value distinct from present-and-empty, or a file appearing never registers as a change (the SSH batched stat emits a `- - -` placeholder that deliberately fails to parse). #transport
- [decision] Cost is not the only reason to short-circuit: an unchanged pass must also write NOTHING to @Observable state, or SwiftUI re-evaluates every cockpit panel per tick regardless of how cheap the read was. #swiftui
- [decision] `ProjectCockpitViewModel.LoadReason` makes the CALLER's intent the gate for expensive work rather than a clock. A `.watcher` load short-circuits and never runs the doctor; `.userInitiated` (project open, refresh button, doctor-sheet close) does both. The 5-minute ProjectHealthCache window used to be the only guard, which meant one tick in every five minutes DID pay for a full registry crawl. #projects

## P2: the short-circuits themselves needed guarding

t-7d05e066, from the P8 post-remediation audit (PERF H1-H3/M1-M4, DI M6/M7). PF made the tick cheap; this round fixed what PF's own machinery got wrong.

- [gotcha] **A wrong answer that is STABLE is worse than no answer.** `SSHTransport.statAll` zipped reply lines onto input paths by POSITION with no count guard. One stray stdout line (a chatty `~/.profile`, "You have mail") shifted every signature by one — and shifted it the same way on every tick, so the cockpit compared two equally-wrong signatures and never reloaded again until the app restarted. A path containing a newline did it deliberately. Each reply line now carries its own input index (`\u{1F}s<i> ` prefix, printed by the remote shell), unmarked lines are ignored rather than counted, newline-containing paths are refused outright, and any reply that isn't accounted for path-by-path returns nil. #transport
- [decision] `statAll` returns `[String: FileStat]?` — **nil means "do not trust this"**, and it is a different thing from an empty map. The old all-or-nothing empty return was turned by `ProjectCockpitViewModel.signature` into a map of `"-"` (absent) entries, which can never match the previous signature, so every transport blip took the FULL facet reload including the derive-and-save of the project record — over the transport that had just failed. That is the stripped-record shape D3 closed, reached through the fast path. `ProjectCockpitViewModel.shouldRead` is now a pure function of (reason, recheckHealth, fresh, last) and answers "no" for a watcher tick with no signature: keep the state, ask again next tick. #projects
- [gotcha] `@Observable` setters do not compare. An unchanged sidebar tick still wrote `projects`, `registryDamage` and `selectedHasDashboard`, so the whole sidebar (O(F·N), with `folderProjects` evaluated twice) re-rendered several times a second while the transport cost was already zero. Each write is equality-guarded now, `selectedHasDashboard` behind a single setter so no call site can forget. Pinned with `withObservationTracking` — both halves: unchanged writes nothing, changed still writes. #swiftui
- [decision] The sidebar's dashboard glyph is a GATED stat, not a per-tick one: it re-probes when the selection changes, when the registry actually changed, on an explicit refresh, and otherwise at most once per 60s. The floor is the point — the gate cannot see `dashboard.json` appearing under an unchanged registry, so without a revalidation window the glyph would be wrong forever. Same shape and same number as `ProjectMenuProbeCache`. #performance
- [decision] Every new short-circuit in this batch carries a working invalidation edge, and that was the review criterion: quarantine dedup is memoized per (path, content-SHA256) with a 300s TTL AND is forgotten when pruning deletes the copy it points at; the kanban widget's tenant lookup (2 blocking SSH round-trips ON THE MAIN THREAD every 10s — the last clear C10 remnant) caches its NEGATIVE result against the manifest's `mtime:size`, so minting a tenant is picked up on the next poll. #projects
- [fact] `.corrupt-*` copies are pruned to the newest 5 on write. Unbounded was not merely untidy: every copy is a file the dedup scan reads in full whenever the memo is cold, so K copies cost 1 + 2K round-trips per cold pass.


## P3: the last per-tick N was the WIDGETS (t-5810202c)

Once PF made the cockpit's facet reload one batched stat and P2 made the short-circuits trustworthy, the dominant per-tick term on a populated dashboard was W — one stat, and one transport construction, per file-reading widget per tick. `statAll` existed and was unused exactly where N was largest.

- [decision] `WidgetSignatureBatch` (`scarf/scarf/Features/Projects/Views/Widgets/WidgetSignatureBatch.swift`) is a per-tick COALESCER, not a cache: the first `markdown_file` / `image` / `log_tail` widget to ask for a tick's signature starts ONE `statAll` over every file-reading path on the dashboard, and the rest await that same pass. 8 widgets = 1 SSH round-trip instead of 8. A new tick is a new pass — it never holds an answer past the tick it was taken for. #performance
- [decision] The path set is supplied BY THE PANEL (`CockpitDashboardPanel`), not accumulated from the widgets themselves. `WidgetSignatureBatch.filePaths(in:projectRoot:)` walks the dashboard the panel is about to render and resolves each path through the same `WidgetPathResolver` gate the widget uses. Registration-from-the-widgets was the obvious shape and is wrong: the pass's coverage would then depend on which widget's `.task` happened to run first. #projects
- [gotcha] Three degradations, and only one of them may ever mean "unchanged" — none of them do. `.known(nil)` (statAll answered, file absent) makes the widget READ, exactly as its own `stat` of a missing file always did; `.unknown` (no scope installed, path not in the set, or `statAll` returning nil) sends the widget to its own single stat, i.e. it degrades to the OLD cost on exactly the ticks where the transport is already failing. A widget can never go stale for want of a batch. Pinned by `WidgetSignatureBatchTests` — the changed-file edge, the uncovered-path edge and the no-scope edge each have their own test. #gotcha
- [decision] `log_tail` joined the stat-first club in this batch. It had NO signature check at all and re-spawned `tail` — a process spawn, an SSH round-trip on a remote context — on every tick per widget, for a log that had not changed. Its skip is keyed on `(signature, lines)`, because the rendered tail is a function of both and `.task(id:)` re-runs on a `lines` change with the same file. #performance
- [gotcha] The narrowing every one of these widgets now accepts: `stat` reports whole seconds, so an in-place rewrite of the SAME byte count inside one second is invisible until something else about the file changes. Logs are appended to and markdown files are rewritten atomically, so size moves; the alternative is a spawn-and-read per widget per tick forever.
- [fact] The tick key is `(watcher stamp, path set)`, not the stamp alone — a dashboard that gains a widget mid-tick must not be answered out of a map taken before that path existed. Cheap, and it removes the one case that could write a wrong "absent" signature into a widget's state for a tick.
- [fact] iOS renders none of the file-reading widget types (its `Projects/Widgets/` has chart/list/progress/stat/table/text/webview only), so this is a Mac-only surface; `WidgetView` is reachable only from `DashboardSectionView`, which is reachable only from the cockpit panel that installs the scope.
