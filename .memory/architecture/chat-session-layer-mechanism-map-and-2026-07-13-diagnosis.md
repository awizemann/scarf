## Mechanism facts (file:line grounded, verified 2026-09-26)
- [fact] One `hermes acp` process per session start — `startACPSession` (ChatViewModel.swift:1807) always `stopACP()` then spawns fresh; config.yaml is read ONLY at spawn. Mid-chat model change = ACP `session/set_model`; global default changes need the next spawn. #lifecycle
- [fact] "Loading session…" spinner = static label gated on `isPreparingSession` (ChatViewModel:379-384). NO timeout bounds the start/resume pipeline, and ChatSessionListPane disables all row clicks while preparing → a wedged start is SELF-LOCKING (restart-only recovery). Watchdog added in Fix 3 bounds this. #spinner
- [fact] Pre-engagement gate (`hasUserSentPromptThisSession` at RichChatViewModel:1810, checked in handleACPEvent at 2138) drops ALL stream events — including the synthesized `promptComplete` — until `addUserMessage` (RichChatViewModel:1955) sets the gate. Turn completion = sendPrompt's RETURN; promptComplete is intentionally NOT gated per Fix 2. #gate
- [fact] Hermes replays full history as session/update notifications inside session/load; Scarf drops them by design and hydrates from state.db. Sidebar counts + info-bar tokens come from state.db reads, NOT stream accounting — a session can look alive in the sidebar while the transcript pane is deaf. #streams

## Confirmed defects (2026-07-13, agent.log + state.db + live probe evidence)
- [gotcha] S1 phantom load: Hermes 0.17 returns `{}` (empty dict, not null) for a not-restorable session/load; ACPClient's guard only catches nil → Scarf attaches to a nonexistent session; next prompt gets stopReason=refusal. 0.17 real load successes carry `models`/`modes` keys — guard must check those. Fixed. #s1
- [gotcha] S2 deaf transcript: sendViaACP's dedup guard matches re-sent text against DB history → skips addUserMessage → gate never opens → every chunk/tool event dropped while the turn runs fine server-side. Fixed by scoping dedup to localEchoAlreadyAdded flag. #s2
- [gotcha] S3 self-locking spinner: wedged pre-spawn start leaves isStartingSession stuck; clicks disabled; no watchdog. Credible contributor: ProcessACPChannel readers BLOCK cooperative-pool threads and are LEAKED by start-failure catch paths. Fixed with 90s watchdog + DispatchSourceRead reader reform. #s3
- [gotcha] S4 duplicated message: one DB row with the text twice — Scarf delivered the same prompt in a killed turn then re-sent it; Hermes' alternation repair merged them. stopACP kills mid-turn processes with NO session/cancel and no transcript feedback. The 2026-07 "fix" (bounded session/cancel) was INERT until P7a (2026-09-26): ACPClient sent session/cancel as a JSON-RPC REQUEST (with id), which the acp lib (0.8.1 and 0.9.0, every supported host) routes only as a NOTIFICATION, so Hermes answered -32601 and never cancelled (proven by a probe against the installed 0.9.0 router). P7a sends it id-less; S4 finalization still races the client.stop() that follows the write (Hermes' acp Connection.close cancels in-flight handler tasks on stdin EOF). #s4

## Fix list (prioritized, task board: t-891c321a / t-60f2f152 / t-5451bd1b)
1. loadSession guard: empty-dict result = not restorable (fall back to newSession). 2. Never gate-drop promptComplete; open gate at actual send sites. 3. Scope dedup guard to the optimistic echo only. 4. Move pipe readers off the cooperative pool.

## Round-6 P58 — the same starvation mechanism was still live in the transports

- [fact] **The `DispatchSourceRead` cure that moved ACP off the wedge stayed private for fourteen months, and the identical blocking loop ran in four other places the whole time.** `LocalTransport`/`SSHTransport` × `streamLines`/`streamRawBytes` each read stdout with `Task.detached { while true { handle.availableData } }`. `HermesLogService` drives them with `tail -F`, which never exits, so one open Logs pane held one cooperative-pool thread for as long as the pane was open — the same "pool thread parked in `read(2)` starves unrelated Swift-concurrency work" mechanism this note's diagnosis names, on a surface nobody connected to it
- [decision] **The reader is `ScarfCore/Transport/PipeReader.swift` now, shared by ACP and the four spawns**, generalised over framing rather than copied. ACP's exact semantics (fail on invalid UTF-8, DROP a trailing partial frame) survive as one `acpLines` factory; the transports take the lenient framing and DELIVER the partial line. If this wedge is ever re-diagnosed, both consumers are one file #c10


## P7b (2026-09-26, t-409ec2da) — currency, cancel and cursor rules

- [gotcha] **A reconnect ladder's `client.start()` / `loadSession` cannot be interrupted** — `stopACP` / iOS `stop()` only cancel the Swift task, and a new start installs its own client meanwhile. Both ladders now re-check after `loadSession` (Mac: `!Task.isCancelled && acpClient == nil`; iOS: `!Task.isCancelled && client === <client the ladder replaces>` — iOS ladders also run from `.failed`/`.offline` with a client still installed, so a nil check there would wedge them) and stop their own client; after the reconcile they only finish wiring while `acpClient === client`. #reconnect
- [fact] **Hermes answers `stopReason: "cancelled"` only for a turn whose `session/cancel` it received** (`_finish_turn`, acp_adapter/server.py:965,999 @ v2026.9.24), and Scarf is the only client of its `hermes acp`. So `cancelled` never raises the failure banner; a cancel Scarf asked for on purpose (voice barge-in → `RichChatViewModel.noteTurnCancelRequested()`) paints no bubble either. `stopACP`'s synthesized mid-turn `cancelled` still paints its bubble (user didn't ask). The composer Stop (B06) calls `noteTurnStopRequestedByUser()` (sets the cancel marker, answers on-screen permissions, paints "You stopped this turn") before `session/cancel`. #cancel
- [gotcha] **Since P7a `session/cancel` is a notification that returns once written.** Calling `client.stop()` right after it closes Hermes's stdin and the acp lib's `Connection.close()` cancels in-flight handlers — the cancel can be cut short (S4 again). `stopACP` now waits for the in-flight turns' `session/prompt` answers inside the same 2 s bound (`boundedSessionCancel(…, awaiting:)`) before `stop()`. #s4
- [fact] **`reconcileWithDB` owns the pagination cursor for the rows it installs**: keeps this session's paged-in rows older than its 200-row window (minus any the window holds a compaction copy of — `CompactionGenerationKey`, B01), sets `oldestLoadedMessageID` to the oldest installed session row, `hasMoreHistory` from a full window (or leaves `loadEarlier`'s verdict when older rows were kept), drops `earlierHistoryCutoffId` when no row below it remains, and returns early if `sessionId` moved. #history
- [fact] `openToolCallIds` is cleared at every turn end (promptComplete, connectionLost, finalizeOnDisconnect); `addUserMessage` finalizes the streaming bubble first while a turn runs; `workingSince` for a DB-poll-detected running turn is seeded from the latest user row on the edge into working. #turn-end
- [gotcha] iOS `runPrompt` now drops a turn whose client was replaced (Mac parity) — including a `processTerminated` that lands after `handleConnectionDied` cleared `client`: that turn ends silently (finalizeOnDisconnect already ended the working state; the reconcile shows what Hermes persisted). #ios


## R09 (2026-09-26, t-b0985b98) — local echo reconciliation is by wire text + watermark

- [fact] **The optimistic user echo is retired against state.db by what went on the WIRE, never by what was typed.** `pendingLocalUserMessages` holds `PendingEcho {message, watermark, matchKeys}`; the send paths call `RichChatViewModel.notePromptWire(displayText:wireText:imageCount:)` (Mac `ChatViewModel.sendViaACP`, iOS `ChatView` send). Keys (`persistedUserRowKeys`): the trimmed wire text; `[]` for a name Hermes's ACP adapter dispatches (help/model/tools/context/reset/compress/version — no agent turn, no row, reply not persisted either); the argument for `/steer` / `/queue` (lands later as a steer-marker row or the queued turn's row); `["[screenshot]", "[Image attachment]"]` for image-only. Hermes stores image prompts as "text\n[screenshot]" (`_durable_content`, agent/session_persistence.py:108-119 — the plain-text persist override is refused for list content, :69-77), wraps post-cancel prompts as "…User correction/guidance after interrupt: <text>" (acp_adapter/server.py:201-202) @ v2026.9.24 #echo
- [decision] `settledEchoIds`: echoes in send order each claim one unclaimed user row with id > watermark (highest persisted id on screen at send; messages.id is a global rowid), standalone compaction summaries excluded; strict shapes first (equal, key+"\n…", "…\n"+key, "…: "+key, "\n"+key+"\n"), plain containment second. Empty keys settle immediately (never re-injected). Same matcher in `loadSessionHistory`, `reconcileWithDB` (which now also prunes the cache) and `mergedAfterPoll`. `notePromptWire` adopts an autostart echo made while sessionId was nil and moves one cached under a session `session/load` fell back away from #echo
- [gotcha] `reset()` closed the data service fire-and-forget; a quick switch-back's `refresh()` could open before the close landed and paint an empty transcript. `reset()` now keeps `pendingDataServiceClose` and `loadSessionHistory` / `reconcileWithDB` await it #history



## R10 (2026-09-27, t-6988d9a5) — autostart replay gate, iOS stall policy, off-main sidebar CLI

- [fact] **Autostart keeps the replay gate shut through `session/load`** (S02-F3). `ChatViewModel.autoStartACPAndSend` echoes, then calls `RichChatViewModel.closeReplayGate()` (the echo had opened it), and before `sendViaACP` waits in `awaitEventLoopDrain(client:)` until the event loop has handled `ACPClient.eventsEmitted` events (`acpEventsHandled` counter, reset per loop; bounded 5 s). Hermes streams the whole stored history inside the load call before answering (`acp_adapter/server.py:579-589`, `_history_replay_updates` :125-167 @ v2026.9.24), so this also closes accepted-low #2 (stragglers after `markPromptSent`) for the autostart path. iOS has no autostart: `_sendImpl` requires `state == .ready` #replay-gate
- [decision] **iOS stall detector = `ACPStallPolicy`** (ScarfCore, S01-F2): 900 s ceiling (terminal foreground cap 600 s + headroom, `tools/terminal_tool.py:75`) while `RichChatViewModel.hasToolCallInFlight` OR a permission prompt is pending — a ceiling, not an exemption, because Hermes self-denies an unanswered prompt after `approvals.timeout` (`acp_adapter/permissions.py:94-113`), so the sheet can outlive the wait. (Correction R18b, t-486aed3f: on >= v0.21.4 Hermes DOES tell the client — it closes the request's own `perm-check-N` / `edit-approval-N` tool call with `status: failed`, permissions.py:102-113 @ v2026.9.24; `RichChatViewModel.closePermissionHermesSettled` now pops the still-queued request and shows "Hermes stopped waiting…". Older hosts send nothing, so the ceiling still matters); 75 s otherwise; silence clock restarts when the user answers a permission (`ChatController.lastPermissionAnsweredAt`). Mac has no read-side stall detector #ios #reconnect
- [fact] **Chat sidebar rename/delete run the CLI off the main actor** via `OffPool.run` with injected `sessionRenameRunner` / `sessionDeleteRunner` (both `@Sendable`); `renameSession` and `deleteSession` are now `async` (S03-F4, and the delete item of t-fa0043f6). `isRenamingSession` disables the sheet's Rename button #c10
- [decision] Bot CLI transport (`BotConversationViewModel.deliverViaCLI`) deliberately does NOT call `notePromptWire`: its keys assume ACP slash dispatch, and the quiet CLI turn hands the text straight to `run_conversation` (`hermes_cli/cli_single_query.py:180-204` @ v2026.9.24), so `addUserMessage`'s default key is already the stored row #echo



## R16b (2026-09-27, t-25209c91) — held sends, rotation, Bot Chat autostart, resume I/O

- [fact] **Sends made while a start path's client is installed but its `session/load` replay is not yet handled are HELD** (`ChatViewModel.heldSends` / `heldSendsClient`): echoed with the replay gate kept shut, sent in order once the path drained (`releaseHeldSends(turnAlreadyRunning:)` — autostart after its own prompt, the reconnect ladder after `awaitEventLoopDrain`, which it now also runs). Held sends pass `turnInFlight` to `sendViaACP` because their echoes already set `isAgentWorking`. A failed autostart drops them with a hint #replay-gate
- [fact] **Compression rotation mid-chat**: Hermes keeps the ACP id and moves its internal session to a continuation, announcing it in `session_info_update` `_meta.hermes.sessionProvenance` (`ACPSessionProvenance`). `RichChatViewModel.noteSessionRotation` extends `lineageSessionIds`; every transcript DB read (load, reconcile, loadEarlier, tool hydration, polling) uses `transcriptSessionIds`. Hosts without the meta: unchanged #rotation
- [decision] **Bot Chat never auto-starts blind**: `ChatViewModel.autoStartInterceptor` (consulted only when `acpClient == nil`) lets `BotConversationViewModel` re-resolve and resume the canonical chat, then send. `verifyCanonicalBinding` accepts a matching id only once the start FINISHED (`!isStartingSession && isACPConnected`) — `loadSessionHistory` names the requested id before a `session/load` fallback re-points it, so a mid-start match can be the drift itself #bot
- [fact] Resume's attribution write/read + registry read run in one `OffPool` batch (C10); the resume path's `Task.detached` reads are `OffPool.run` (P60). `renameError(for:)` scopes a rename failure to its own sheet #c10


## R17 additions (2026-09-27)
- [invariant] `ACPClient` writes every request/notification/permission reply in ISSUE order through a `writeTail` task chain (`enqueueWrite`); independent detached writes let two back-to-back prompts (held sends released after a load) or a `session/cancel` reach Hermes out of order. Keepalive is not queued (standalone line) #acp
- [invariant] Sends typed while the reconnect ladder runs (no client yet) are echoed and HELD (`holdingForReconnect`), released after the ladder's client drains its load replay; sends already held for a dying client are carried into the ladder; dropped with the "couldn't be sent" hint on exhaustion or bow-out, silently on `stopACP`. They used to auto-start a second `hermes acp` #chat
- [invariant] A Live Voice turn submitted while `heldSendsClient === acpClient` (load replay undrained) answers busy instead of calling `markPromptSent` #voice
