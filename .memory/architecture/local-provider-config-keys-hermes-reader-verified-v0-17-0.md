Reader-verified 2026-07-13 against the LIVE local Hermes install: **Hermes Agent v0.17.0 (2026.6.19), upstream 291eae63**, source at `~/.hermes/hermes-agent` (the venv `hermes` binary runs this checkout). All claims cite the code that `resolve_runtime_provider()` actually executes at request time (hermes_cli/runtime_provider.py + hermes_cli/auth.py) — NOT `hermes config set` acceptance, per the v0.18 gotcha. Gateway agents use the exact same reader (gateway/run.py:1790 calls `resolve_runtime_provider()`), so no extra keys are needed for gateway/remote sessions.

## The one table that matters at runtime
- [fact] There are TWO alias tables and they DISAGREE. Catalog-side (hermes_cli/providers.py:346-355): `ollama`→`custom`, `vllm`/`llamacpp`/`llama.cpp`/`llama-cpp`→`local`, `lm-studio`→`lmstudio`. Runtime-side (hermes_cli/auth.py:1560-1564, inside `resolve_provider`): `ollama`→`custom`, **`vllm`/`llamacpp`/`llama.cpp`/`llama-cpp`→`custom`** (NOT local), `lm-studio`→`lmstudio`. The runtime table is authoritative for chat requests. #aliases
- [constraint] **`model.provider: local` FAILS at request time.** "local" appears in NO runtime alias and NOT in PROVIDER_REGISTRY (auth.py:169-439 — registry keys checked exhaustively; grep '"local"' in auth.py = zero hits). `resolve_provider("local")` raises AuthError "Unknown provider 'local'" (auth.py:1595-1602) unless the user happens to declare a `providers.local` / `custom_providers` entry literally named "local" (matched by `_get_named_custom_provider`, runtime_provider.py:504-658, before resolve_provider runs). Scarf's mirror of providers.py ALIASES (`vllm`→`local`) is a catalog label only — the UI must write `vllm`/`llamacpp` (→custom) or `custom`, never `local`. #hazard

## (a) Bare `ollama` (→ custom at runtime)
- [fact] **No hardcoded localhost:11434 and no OLLAMA_HOST anywhere** — grep across the whole tree: OLLAMA_HOST is never read. The base URL comes ONLY from: explicit arg > `CUSTOM_BASE_URL` env > `model.base_url` (config.yaml) > `OPENROUTER_BASE_URL` env > OpenRouter default (runtime_provider.py:970-976). If `model.base_url` is unset, a bare-ollama chat **silently falls through to OpenRouter** — that is the failure mode, not a connection error. #gotcha
- [fact] Required config for working bare-ollama chat: `model.provider: ollama` (or custom/vllm/llamacpp) + `model.base_url: http://<host>:11434/v1` + `model.default: <tag>`. Trust gate `_config_base_url_trustworthy_for_bare_custom` (runtime_provider.py:60-87, applied :965-968): model.base_url is honored for ANY host (LAN/WireGuard OK) when `model.provider` is custom or resolves-to-custom (ollama/vllm/… — GH #27132); if model.provider is stale/something else, only loopback hosts are trusted and openrouter.ai is always rejected.
- [fact] No dummy api key needed: key candidates are host-gated (OLLAMA_API_KEY only for ollama.com hosts, GHSA-76xc-57q6-vm5m; runtime_provider.py:1006-1024), loopback yields no host-derived key (`_host_derived_api_key` returns "" for IPs/localhost, :137-145), and the resolver substitutes the placeholder **"no-key-required"** itself (runtime_provider.py:847, :908, :1049-1050) because the OpenAI SDK requires a non-empty string. Optional inline `model.api_key` is read too (:932-937, only when config base_url is used).
- [fact] api_mode: `model.api_mode` if set and valid, else URL auto-detect, else `chat_completions` (:1054-1056). Valid set `_VALID_API_MODES` = chat_completions | codex_responses | anthropic_messages | bedrock_converse | **codex_app_server** (:255-268 — the fifth entry, a codex-subprocess runtime opt-in added 2026-05-13 in 091d8e103, was MISSED by the original verification pass; the T1 audit corrected LocalModelProviders.swift accordingly). `_parse_api_mode` (:269-276) does `raw.strip().lower()` — case-insensitive and whitespace-trimmed, NOT exact-string matching; anything not in the set is silently ignored — another config-set-accepts-anything trap.

## (b) `lmstudio`
- [fact] Confirmed: PROVIDER_REGISTRY["lmstudio"] (auth.py:205-212) — `inference_base_url="http://127.0.0.1:1234/v1"`, `base_url_env_var="LM_BASE_URL"`, `api_key_env_vars=("LM_API_KEY",)`. Resolution (api-key-provider branch, runtime_provider.py:1791-1844 → `resolve_api_key_provider_credentials` auth.py:6252-6296): base_url = `model.base_url` (ONLY when `model.provider: lmstudio`, runtime_provider.py:1799-1803) > `LM_BASE_URL` env > the 127.0.0.1:1234/v1 default. api_key = LM_API_KEY if set, else auto-placeholder **"dummy-lm-api-key"** (`LMSTUDIO_NOAUTH_PLACEHOLDER`, auth.py:145, applied :6272-6274) — user never needs to configure a key. api_mode: chat_completions.
- [fact] Bonus runtime behavior: Hermes JIT-loads the model — `ensure_lmstudio_model_loaded` (hermes_cli/models.py:2993+) probes the server and POSTs `/api/v1/models/load` with a target context length, invoked from agent init (agent/agent_init.py:1560). Model id must match the LM Studio `key`/`id`.

## (c) `local` / vllm / llama.cpp
- [fact] See constraint above: vllm/llamacpp are runtime-aliased to `custom` (auth.py:1563-1564) and follow EXACTLY the bare-ollama path — same keys (`model.base_url` required, same trust gate, same "no-key-required"), no assumed endpoint of their own. `local` as a provider string is only a display label ("Local endpoint", providers.py:372) and a catalog alias target; at request time it errors.

## (d) `custom` with explicit base_url + `custom:<name>` scoped providers
- [fact] Bare form (config.yaml): `model: {provider: custom, base_url: <url>, default: <model>, api_key?: <inline>, api_mode?: <valid mode>}`. Reader: `_get_model_config` (runtime_provider.py:198-217) → `_resolve_openrouter_runtime` (:923-1060). `model.model` is accepted as alias for `model.default` (:203-205). If `model.default` is empty AND base_url is loopback, Hermes auto-detects a single loaded model via GET `<base_url>/v1/models` (:206-213, `_auto_detect_local_model` :175-195; same in cli.py:3571-3577).
- [fact] Named form, NEW style `providers:` dict (read at :546-606): `providers.<key>: {base_url|url|api (one required), key_env?, api_key?, default_model?, api_mode?|transport?, extra_body?, max_output_tokens?|max_tokens?, name?}`. Select it with `model.provider: <key>` or `custom:<normalized-key>`. A user-declared `providers.<name>` beats built-in aliases (providers.py resolve_provider_full step 0, :715-726).
- [fact] Named form, LEGACY `custom_providers:` LIST (must be a YAML list; a dict logs a warning and is ignored, :610-616): entries `{name (required), base_url (required), api_key?, key_env?, provider_key?, api_mode?, model?, extra_body?, max_output_tokens?}` (:622-656). Menu key = `custom:<name lowercased, spaces→hyphens>` (`custom_provider_slug` providers.py:616-623; matching runtime_provider.py:629-634). Resolved runtime provider id is always the string `"custom"` (billing class), source `custom_provider:<name>`.
- [fact] Named-custom api_key order (runtime_provider.py:888-908): explicit > entry `api_key` > `key_env` env value > OPENAI_API_KEY/OPENROUTER_API_KEY (host-gated to their own hosts, #28660) > host-derived `<VENDOR>_API_KEY` > "no-key-required". api_mode: entry `api_mode`/`transport` > URL auto-detect > chat_completions (:902-906).

## (e) Gateway / proxy
- [fact] `gateway/run.py:1783-1790` — gateway-created agents call the identical `resolve_runtime_provider()`; config.yaml is the single source of truth (env vars deliberately not consulted for behavioral config). Nothing extra for local providers. `hermes proxy` (hermes_cli/proxy/server.py docstring, :1-11) is a credential-attaching forwarder for upstream OAuth adapters — unrelated to local providers, as previously recorded.

## (f) Slash / ollama-tag (`llama3:8b`) hazards
- [fact] `llama3:8b` is SAFE end-to-end: the model string is sent verbatim; the only colon-splits (`raw.split(":")[0]`, hermes_cli/models.py:2025, 2069) are OpenAI/Anthropic fast-mode heuristics — no-ops for local models. `custom:` provider-key colons are a different field; no collision.
- [fact] Slash handling is prefix-matched, not blind: `_strip_matching_provider_prefix` (model_normalize.py:226-244) strips `provider/` only when the prefix normalizes to the target provider, so `hf.co/user/model:Q4` survives on a custom provider. ONE real trap: simple `model.aliases` values split once on "/" as `provider/model` (model_switch.py:249-250) — an alias value `hf.co/mistral/x:Q4` mis-parses provider="hf.co". Don't write slash-bearing local model ids into `model.aliases` without a provider prefix intent.
- [fact] Ollama-specific runtime guards keyed off the URL (provider is "custom" by then): GLM-on-Ollama stop-misreport continuation triggers on `:11434`/"ollama" in base_url (run_agent.py:1369-1389); undersized Ollama context halts the turn with `ollama_runtime_context_too_small` (agent/conversation_loop.py:927-933) — remedy is server-side `OLLAMA_CONTEXT_LENGTH` (hint printed at cli.py:5903-5906), or `model.context_length` in config.yaml for the generic case.

## Write-plan ordering contract (T4 integration audit, 2026-07-13)

- [decision] `LocalModelConfigPlan` orderings are crash/abort-safe by construction (commit e0ac2bb). Each op is its own `hermes config set` process and `applyModelConfigPlan` aborts on first failure, so every plan PREFIX is a config a chat may run against. Invariant: no prefix may read as `model.provider: <local alias>` without its `model.base_url` — that state silently falls through to OpenRouter (runtime_provider.py:970-976), leaking a local-intent prompt to a cloud endpoint.
- [fact] Local saves: clears → base_url/api_key/api_mode sets → model.default → **model.provider LAST** (the commit point). Pre-commit writes are inert under the old provider: every reader path gates model.base_url/api_mode on the configured provider matching the one being resolved (anthropic branch, api-key branch runtime_provider.py:1799-1803, `_config_base_url_trustworthy_for_bare_custom`).
- [fact] Remote saves: provider → model.default → **clears LAST**, and clears are skipped for keys the caller knows are already empty (never-local users keep the classic two-op write). Empty model now CLEARS model.default (Nous "leave blank" contract) instead of skipping.
- [fact] Preflight: `ModelPreflight.check` accepts provider=custom + empty model.default + auto-detect loopback base_url as configured; `confirmModelPreflight`'s remote path routes through the plan (was `setModelAndProvider`, which never clears).
- [fact] Reader auto-detect gate is a **case-sensitive substring** check — `"localhost" in base_url or "127.0.0.1" in base_url` (`_get_model_config`, runtime_provider.py:209) — narrower than `_loopback_hostname` (the trust gate, which also takes ::1/0.0.0.0). UI empty-model gating must use `LocalModelProvider.hermesAutoDetectsEmptyModel` (strict subset), never a generic loopback check.
- [fact] `hermes config set <key> ""` verified to WRITE an empty string, not delete: `set_config_value` (hermes_cli/config.py:7025) — "" survives the bool/int/float coercion and `model.api_key` misses the `.env` routing (the `_API_KEY` suffix test fails on the `.` separator), landing in config.yaml via `_set_nested` + atomic write. On failure the CLI never echoes the value (managed-scope message names the key only); success echo masks credential-shaped keys via `mask_secret`.
- [fact] RESOLVED (t-9657430b, commit 35e901e): the residual out-of-plan writers (`alignProviderToModelPrefix`, `stripPrefixFromModelDefault`, the credential-pools post-auth swap) now route through `LocalModelConfigPlan` via a new `operations(selectingRemoteModel:provider:current: HermesConfig)` overload — the one seam mapping the parsed config's local-key fields onto the plan's current-value params, so already-unset keys skip their clears (T4 two-op parity). strip-prefix keeps the provider → plan emits NO clears (semantics unchanged, test-pinned). The pools swap's empty model now CLEARS model.default (matches its "Hermes will pick a default" copy). `HermesFileService.setModelAndProvider` is marked LEGACY — sole remaining caller is iOS ChatView's preflight; no new call sites. The chat preflight also now passes currentContextLength (closes the fd61272d conservative-clear residual). ModelPickerSheet's round-tripped model.api_key renders in a SecureField.

## t-fd61272d implementation facts (2026-07-13, commit 89107d2)

- [fact] **`model.context_length`'s warning-free unset is `0`, not `""`** — `""` is NOT a silent unset for this key: the reader does `if value is not None: int(value)` (agent_init.py:1469-1490), so a present `''` raises ValueError and prints the "Invalid model.context_length" warning on EVERY startup. A non-positive int parses silently and every consumer ignores it: `config_context_length > 0` gates the override (model_metadata.py get_model_context_length step 0, pinned upstream by tests/agent/test_model_metadata.py::test_config_context_length_zero_is_ignored) and the LM Studio preloader does `max(value or 0, MINIMUM_CONTEXT_LENGTH)` (run_agent.py:682). `LocalModelConfigPlan.Operation.clear` therefore emits `config set model.context_length 0` for this key and `""` for the other three. #reader #context-floor
- [fact] `model.context_length` is now the FOURTH member of `LocalModelConfigPlan.localManagedKeys`, clear-ONLY (no descriptor writes it — the picker offers no override UI because the override is a runtime trap). Every local save scrubs it; remote switches clear it unless the caller knows it already reads as unset (empty or int <= 0; garbage like "256K" is deliberately treated as SET so the scrub silences its startup warning). `HermesConfig.modelContextLength` (raw scalar string, parsed in both HermesConfig+YAML.swift and HermesFileService.parseConfig) feeds the Settings path so never-local users keep the classic two-op write. Residual: ChatViewModel's remote-plan call doesn't pass it → conservative clear (writes silent `0`) on chat-side provider switches.
- [fact] Ollama per-model context enumeration: ONE batched curl per listing — `--next` per-URL segments, each `-d {"model":"<name>"} -w <0x1E> <base>/api/show`, deliberately NO `-f` (an HTTP 404 yields a JSON error body + separator so response↔name correlation survives; `-w` output is emitted even for failed transfers — verified live). 0x1E cannot appear in valid JSON or in a name that passed the allowlist (`validatedOllamaModelName`: alnum + `.-_:/@`, <= 256 chars), so segment-count mismatch → discard whole batch, never misattribute. `model_info` key is `<general.architecture>.context_length` with a sorted suffix-match fallback for unknown arches. Live gradient on this Mac: llama3.1:8b=131072 (allowed), qwen2.5:14b=32768 / llama3:70b=8192 / llama3:latest=8192 (blocked by `LocalModelContextGate`, floor 64_000). #enumeration
