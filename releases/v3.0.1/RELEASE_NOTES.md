# Scarf v3.0.1

A fast follow to 3.0.0 that fixes bot creation for real-world profiles and closes an entire class of parsing bugs: Scarf's readers and writers of Hermes-authored files are now tested against output generated by Hermes's **own** serializer, not hand-typed approximations — and every mismatch that hunt found is fixed here.

## Bot creation works for every profile

Creating a bot — or promoting an existing profile with "Make a Bot" — could fail with a refusal to write `profile.yaml`, even though Hermes itself had just written that file. Root cause: Hermes persists profiles through PyYAML, which wraps any value longer than ~80 columns onto continuation lines; Scarf's surgical profile writer read those continuation lines as a nested block and refused to touch the file. **Any bot whose role description ran past one line was unwritable.** Both the reader and writer now understand PyYAML's wrapped scalars — values read back whole, rewrites preserve them byte-faithfully, and the refusal guard still rejects genuinely ambiguous files. Verified end-to-end against real Hermes-created profiles.

The create sheet itself got friendlier too: the profile id now derives from the bot's name as you type (**SEO Research Bot** → `seo-research-bot`) until you hand-edit it, and when Create is disabled the sheet says why, right next to the button — previously a required field could sit scrolled out of view and leave the button silently dead.

## Bot conversations actually reach the bot

Dogfooding the fix above surfaced something deeper: Hermes's ACP adapter only reopens sessions *it* created — and the canonical "Bot Chat" is never one of those (Scarf creates it through the CLI; Hermes Desktop creates it through the gateway). So opening a bot conversation fell back to a fresh untitled session, and Scarf's safety check refused it — correctly, since an untitled session isn't in bot mode at all. The result: fresh bots showed a misleading "couldn't open" error. v3.0.1 routes by the session's birth: ACP-born chats keep live token streaming, and CLI/gateway-born chats — every Bot Chat that exists in practice — deliver each message exactly the way Hermes's own bot-DM tool does and refresh the transcript from the bot's state.db. Replies arrive when each turn completes, the UI says so honestly, and this is now proven end-to-end against the real `hermes` binary in tests, not a scripted stand-in.

## Chat quality-of-life

- The session info bar is now two rows: identity on top, telemetry (model, tokens, reasoning, compactions, cost, elapsed) below — numbers never wrap or clip; only the model name truncates.
- New eye-toggles in the bar show or hide tool calls and reasoning in the transcript on the spot, remembering your preferred density style from Settings → Display.
- The tool-approval dialog is wider, its detail lives in a scrollable, selectable well (long security-scanned scripts no longer stretch the dialog), and its buttons wrap instead of clipping.
- Renaming a session updates the chat header immediately, in every window — no refresh needed.
- The sidebar footer now shows the connected host's Hermes version; Scarf's own version stays in About.

## The parser hunt

The bot bug was one instance of a pattern, so we audited every file Scarf reads or writes that Hermes authors, comparing against real serializer output at the tagged Hermes source. Everything found is fixed:

- **Local-model reasoning overrides save again.** Model ids with colons (`llama3:8b`, `qwen2.5-coder:32b` — the normal case for Ollama and LM Studio) were split at the first colon after Hermes rewrote config.yaml, which made the reasoning-overrides editor silently refuse to save anything. Keys now parse by YAML's own rule.
- **Long quick commands no longer truncate.** PyYAML's line wrapping could cut a quick command at ~80 columns — meaning the slash menu could **execute a prefix of your shell pipeline** and saving the row made the loss permanent. Wrapped values (quick commands, the secrets command, personality prompts, peer notes) now read back complete.
- **One bad cron record no longer blanks the board.** `jobs.json` now decodes per-record with the same tolerance Hermes's own reader uses (`enabled` defaults on, missing schedules allowed); an irrecoverable record is skipped and logged instead of taking every job with it.
- **No more duplicate gateway sections.** A platform section Hermes emitted as an empty inline mapping (`slack: {}`) is now recognized as existing rather than appended a second time.
- **Dotted quick-command names appear on iOS.** A command named `v1.2_deploy` now shows in the ScarfGo slash menu, matching the Mac.

## Under the hood

- Release builds now compile with **warnings as errors**, and the two residual concurrency-capture issues that surfaced were fixed — plus a full sweep that cleared all 46 Swift 6 promoted diagnostics, including a live VoiceOver bug where interpolated labels could read debug descriptions aloud.
- New test infrastructure generates YAML/JSON fixtures at test time with Hermes's exact serializer options, so this class of bug now fails the build instead of shipping. ScarfCore stands at 1,838 tests; Mac and iOS suites green.
- Anonymous usage analytics (same privacy contract as ever — fixed-vocabulary event tokens, never names, text, or paths) now cover the bot lifecycle, so we can see whether Bots is earning its place: created/promoted, edited by aspect, removed, routines, and peer messages. Opt out any time in Settings → Advanced.
